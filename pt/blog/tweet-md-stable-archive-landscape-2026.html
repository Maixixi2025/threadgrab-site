Algumas semanas são cheias de notícias; esta não é. O tweet.md, o conversor X-para-Markdown lançado em maio de 2026, está em silêncio desde sua última entrada de changelog em 27 de agosto de 2026 (um "demo gratuito" junto com datas de publicação e edição em cada post). A homepage está estável, o dateModified do JSON-LD marca 2026-08-24, e o último sinal de produto é — nas palavras do próprio tweet.md — "Try a no-charge demo". Essa é a semana inteira.

Para um arquivista, uma semana quieta é dado. Ela mostra quais ferramentas sobreviveram à primeira onda do lançamento, quais recursos viraram commodities, e quais lacunas ninguém está com pressa de preencher. Este post é um retrospecto do cenário de ferramentas: onde o mercado X-para-Markdown está no fim de agosto de 2026, quando tweet.md é a escolha certa, e onde o ThreadGrab cobre o resto.

Resumo rápido: tweet.md agora é um conversor estável, pago, exclusivo para X, com forte ergonomia de API para agentes (Next.js no Cloudflare, pacotes de créditos $5–$49, frontmatter Obsidian YAML, perfil-como-Markdown). ThreadGrab é um arquivador gratuito, multiplataforma (X + Bluesky + LinkedIn), com uma API de perfil pública e interface trilíngue. Use tweet.md quando quiser snapshots de perfil no seu vault Obsidian; use ThreadGrab quando quiser um arquivo gratuito, durável e multiplataforma que não dependa da página de preços de um único fornecedor.

O que tweet.md é, três meses depois

tweet.md foi lançado em 17 de maio de 2026 como conversor de posts, threads, Articles e perfis do X. O slogan da homepage é exatamente o que ele faz: Convert X/Twitter posts, threads, Articles, and profiles to clean Markdown for LLMs, agents, research, and archives. Just swap x.com for tweet.md. O site é uma build Next.js (App Router) no Cloudflare, servida da edge em Singapura com server-side rendering completo — o H1, as quatro abas de input (Single post / Thread / X Article / Profile) e o JSON-LD estão todos na primeira resposta, não em um shell client-side.

A superfície de produto é mais estreita do que a homepage sugere. A saída são exatamente dois formatos: markdown (padrão) ou obsidian (Markdown com frontmatter YAML para um vault Obsidian). A documentação é explícita: “plain text, never JSON”. As opções de query incluem format, thread (padrão branch-5, faixa 2–500), userinfo, stats, metadata e apikey. Os endpoints são /i/api/convert e /i/api/profile. Não há Bluesky, nem LinkedIn, nem Mastodon, nem Threads.

O que tweet.md custa, e o que não está declarado

O preço é em pacotes de créditos: $5 / 200 créditos, $19 / 1.000, $49 / 3.000 (por crédito $0,025 → $0,019 → $0,0163). Sem assinatura, sem por-usuário. A autenticação é API key, header Bearer, cookie de sessão, ou uma lista de IPs confiáveis — múltiplas chaves por conta são permitidas. Demos controlados para um perfil de teste *t-twmduser são gratuitos.

O que não é publicado: limites de taxa. O site não lista um teto de taxa em lugar visível, o que importa para uma ferramenta que cobra por chamada. Se você constrói um agente em cima do tweet.md, está confiando no throttle silencioso do fornecedor — um risco que você pode evitar comprando um pacote de créditos e tratando cada requisição como um gasto medido. Para fluxos de pesquisa que puxam milhares de posts por vez, a ausência de limite de taxa declarado é uma bandeira amarela.

Onde o ThreadGrab cobre terreno diferente

ThreadGrab fica na mesma categoria — capturar conteúdo social público como Markdown — mas com três diferenças estruturais que importam para arquivistas.

  • Multiplataforma: X, Bluesky, LinkedIn e (via o pipeline de captura headless) qualquer página web renderizada. tweet.md é apenas X.
  • Gratuito, sem conta: o pipeline de arquivamento do ThreadGrab e o endpoint público /api/profile/{username} não exigem API key nem pagamento.
  • Interface trilíngue: EN / PT / ID. tweet.md é apenas inglês, sem superfície de localização no source.

O formato gratuito + multiplataforma + trilíngue é o motivo pelo qual a cobertura do ThreadGrab se sobrepõe ao tweet.md no X mas se estende a plataformas onde tweet.md não consegue seguir — e por que as duas ferramentas se lêem como complementos, não substitutas.

O fluxo de arquivamento da "semana quieta"

Quando nada está lançando, o movimento certo é endurecer o arquivo existente. Aqui vai um fluxo que combina snapshots de perfil amigáveis ao Obsidian do tweet.md com capturas gratuitas e duráveis de thread do ThreadGrab, mantidas lado a lado em uma pasta para que o texto legível e a proveniência estruturada viajem juntos.

my-archive/
  tweet-md-profiles/
    2026-08-28-handle-profile.md        # Obsidian YAML frontmatter
  threadgrab-threads/
    2026-08-28-same-thread.md           # clean Markdown, no metadata
    2026-08-28-same-thread.json         # structured sidecar (re-fetchable)
  README.md

Use tweet.md para o snapshot de perfil que você quer manter no seu vault Obsidian (frontmatter YAML, tags, dataview-friendly). Use ThreadGrab para a thread em si (texto completo + sidecar JSON que você pode re-buscar depois). Os dois formatos são deliberadamente diferentes: tweet.md te dá um nó de knowledge-graph; ThreadGrab te dá uma citação. Um arquivo precisa dos dois.

Uma checagem rápida de captura

Para capturas pontuais, o teste mais simples é se o padrão de URL que você já tem funciona na ferramenta que você está usando. Aqui está o formato que ambas as ferramentas esperam, lado a lado:

# tweet.md: troque o host
https://x.com/handle/status/123...  ->  https://tweet.md/i/status/123...

# ThreadGrab: mesmo handle, API de perfil pública
https://threadgrab.com/api/profile/handle

# Ambas retornam Markdown; tweet.md adiciona frontmatter YAML
# Obsidian no flag de formato obsidian, ThreadGrab retorna Markdown limpo
# mais um sidecar JSON opcional que você pode re-buscar.

Se você se pega trocando x.com por tweet.md na barra de URL várias vezes por dia, está pagando pela conveniência do Obsidian. Se você se pega colando a mesma URL de perfil do ThreadGrab num script, está montando o caminho de arquivo durável. As duas são jogadas honestas.

Quando usar qual, em três regras curtas

  • Use tweet.md quando o entregável é um snapshot de perfil ou thread amigável ao Obsidian, quando você está okay pagando por chamada, e quando você só precisa de X.
  • Use ThreadGrab quando o entregável é um arquivo gratuito, durável e multiplataforma, quando você precisa de uma API pública sem auth, ou quando seus leitores não são apenas em inglês.
  • Use os dois quando você quer o nó YAML do Obsidian e a thread Markdown durável, e está disposto a gastar alguns créditos para acertar o frontmatter.

O que um mercado estável realmente significa

Uma semana quieta não é uma categoria morta — é uma categoria que encontrou seu formato. tweet.md domina o nicho X-only, Obsidian-first, API-para-agentes; ThreadGrab domina o nicho multiplataforma, gratuito, trilíngue. Nenhum está correndo para absorver o outro. A leitura honesta é que o mercado X-para-Markdown em agosto de 2026 está segmentado, não em consolidação: os conversores que sobrevivem são os que escolhem uma vantagem estrutural (pago + agent-first, ou gratuito + multiplataforma) e param de perseguir o outro lado.

Para arquivistas, isso é boa notícia. Dois fornecedores duráveis é melhor que um. Os riscos a observar estão em cada lado: os limites de taxa não declarados e o escopo de plataforma única do tweet.md; a dependência do ThreadGrab de as plataformas sociais não mudarem sua superfície de API pública de baixo dele. Nenhum vai sumir este mês — ambos valem a pena integrar a um fluxo de arquivamento de longo prazo.

FAQ

O tweet.md é gratuito?

Parcialmente. tweet.md vende pacotes de créditos ($5 / $19 / $49) e oferece um demo gratuito para um perfil de teste *t-twmduser. Para conversões reais de perfil ou thread, você paga por chamada. Não há assinatura nem tier gratuito para uso em produção.

Quais plataformas o tweet.md suporta?

Apenas X / Twitter — posts, threads, Articles e perfis. Não há suporte a Bluesky, LinkedIn, Mastodon ou Threads na superfície visível do produto.

O tweet.md gera JSON ou dados estruturados?

Não. A documentação é explícita: a saída é texto plano, seja Markdown ou Markdown com frontmatter YAML para Obsidian. Se você precisa de JSON estruturado, tem que fazer parse do Markdown você mesmo ou usar outra ferramenta.

O tweet.md publica limites de taxa?

Não. Não há limite de taxa por segundo ou por dia publicado em nenhum lugar visível da documentação. Trate cada requisição como um gasto medido contra seu saldo de créditos e faça backoff em respostas 429 em vez de confiar em uma quota declarada.

Como o ThreadGrab é diferente do tweet.md?

ThreadGrab é gratuito, multiplataforma (X + Bluesky + LinkedIn + web headless) e vem com uma API pública de perfil sem auth. tweet.md é pago, apenas X, e vem com saída YAML amigável ao Obsidian. Use o que combina com seu formato de arquivo; ambos valem a pena manter.

Devo trocar de tweet.md para ThreadGrab (ou vice-versa)?

Só se o formato do seu arquivo mudar. Se você precisa de cobertura multiplataforma, captura ilimitada gratuita ou interface trilíngue, vá para ThreadGrab. Se você precisa de frontmatter YAML do Obsidian, ergonomia de API para agentes e está feliz pagando por chamada, fique com tweet.md. Muitos arquivistas rodam os dois lado a lado.

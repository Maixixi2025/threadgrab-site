O Panache resolve exatamente essa classe de problema, em um único CLI.

Por Que Threads Capturados Precisam de um Formatador e Linter

Uma captura de thread é uma cópia fiel da fonte, o que é exatamente o que você quer para um arquivo — mas raramente é o que você quer publicar. Quando você converte um thread de vários posts para Markdown, o resultado tende a ter:

  • Larguras de linha inconsistentes. Cada autor quebra o texto de um jeito, então o arquivo capturado mistura linhas curtas e longas.
  • Estilos de lista misturados. Um thread pode usar 1., - e * de forma intercambiável, e colar isso num editor gera renderização inconsistente.
  • Quebras irregulares. O reflow de parágrafos difere de post para post, então o arquivo fica desigual.
  • Blocos de código sem formatação. Tweets com código ou configuração chegam como texto puro, sem indentação ou estilo de sintaxe consistente.

Nada disso quebra a renderização, mas tudo isso torna o Markdown mais difícil de editar e menos profissional quando você republica. Um formatador normaliza a estrutura; um linter diz o que precisa de correção; a auto-correção faz isso por você.

O Que o Panache Faz (Verificado)

O Panache é open source no GitHub (licença MIT), escrito em Rust e distribuído por dezenas de canais, incluindo cargo install, Homebrew, npm, PyPI via uv tool ou pipx, e um script de instalação oficial. Três capacidades importam para o fluxo de republicação:

  • Formatação — reformate um arquivo no lugar, pelo stdin ou por padrões glob, com largura de linha e estilo de reflow configuráveis. A formatação é idempotente, então rodar duas vezes dá o mesmo resultado.
  • Auditoria (lint) — relate problemas de formatação com panache lint e, opcionalmente, auto-corrija. A flag --check do comando format verifica se um arquivo já está limpo sem alterá-lo, ideal para CI.
  • Formatadores e linters externos de blocos de código — rode Prettier em JavaScript, ruff ou black em Python, ou sua própria ferramenta nos fenced code blocks dentro do Markdown, mantendo cada exemplo de código consistente.

Ele também inclui um language server (LSP) completo para recursos do editor — diagnósticos, code actions, outline do documento e ir para a definição de referências — então o mesmo motor funciona dentro do VS Code ou do editor de sua preferência. A página de performance o compara com Prettier, mdformat, markdownlint e outros, e a página de comparação mostra exatamente onde ele lida com sintaxe Quarto/Pandoc que as ferramentas mais antigas não cobrem.

Instale o Panache

Escolha o método de instalação que se adapta à sua máquina. No macOS e Linux, o script oficial é o caminho mais curto:

# Script de instalação oficial (macOS / Linux)
curl --proto '=https' --tlsv1.2 -sSf https://panache.bz/install | sh

# Ou por gerenciadores de pacotes
cargo install --locked panache
brew install panache
npm install -g @panache-cli/panache
uv tool install panache-cli   # ou: pipx install panache-cli

Depois de instalar, confirme que funciona:

panache --version
panache format --help

Passo 1 — Capture o Thread e Depois Formate

Converta o thread público do X para Markdown com o ThreadGrab e depois normalize com panache format. A etapa de captura dá a você uma fonte fiel; a etapa de formatação dá uma fonte limpa.

# 1. Capture o thread público do X como Markdown limpo
threadgrab https://x.com/you/status/1234567890123456789 \
  --output ./drafts/thread-2026-08.md

# 2. Formate no lugar, refluindo para a largura de linha escolhida
panache format ./drafts/thread-2026-08.md

# 3. Ou envie um único arquivo pelo stdin
cat ./drafts/thread-2026-08.md | panache format

O Panache lê a configuração de .panache.toml no diretório atual ou em um diretório pai, então você pode fixar o estilo uma vez e reutilizá-lo em todos os arquivos capturados. Uma configuração mínima que reflui parágrafos para uma largura confortável fica assim:

# .panache.toml
[format]
wrap = "reflow"
line-width = 80
line-ending = "auto"

Passo 2 — Audite e Auto-Corrija Antes de Republicar

Antes de republicar, rode o linter para detectar o que a formatação deixou para trás e deixe-o corrigir o que puder:

# Relate problemas de formatação em todos os threads capturados
panache lint ./drafts/*.md

# Verifique se um arquivo já está limpo (código de saída não-zero se não estiver)
panache format --check ./drafts/thread-2026-08.md

# Formate + corrija um diretório inteiro de capturas de uma vez
panache format ./drafts/**/*.md

Como --check retorna um código de saída significativo, você pode colocá-lo em qualquer script ou job de CI: se um thread capturado não estiver formatado, o job falha e você sabe exatamente qual arquivo corrigir.

Passo 3 — Mantenha Blocos de Código Consistentes com Formatadores Externos

Threads que incluem código ou configuração são onde a formatação realmente compensa. O Panache roda formatadores externos nos fenced code blocks, então você mantém cada exemplo de código consistente com as mesmas ferramentas que já usa. Adicione uma seção [formatters] à sua configuração:

[formatters]
python = ["isort", "black"]
javascript = "prettier"
typescript = "prettier"

[formatters.prettier]
prepend-args = ["--print-width=100"]

Agora, ao formatar um thread capturado que contém trechos de Python ou JavaScript, o Panache passa esses blocos por isort + black ou Prettier automaticamente. O Markdown narrativo é normalizado pelo Panache; o código embutido é normalizado pela ferramenta que o seu projeto já padronizou.

Passo 4 — Imponha Automaticamente com Pre-commit ou CI

O passo final é eliminar a necessidade de lembrar. O Panache oferece um hook de pre-commit e uma GitHub Action dedicada, então cada arquivo Markdown capturado é formatado e auditado antes de entrar no seu repositório ou na saída publicada.

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/jolars/panache-pre-commit
    rev: v3.4.0
    hooks:
      - id: panache-format
      - id: panache-lint
# GitHub Actions — no seu arquivo de workflow
- uses: jolars/panache-action@v1

Com um hook de pre-commit em vigor, o pipeline fica totalmente automático: capture o thread com o ThreadGrab, faça commit, e o Panache formata + audita antes de o commit ser salvo. Markdown limpo vira o padrão, não a exceção.

FAQ

O que é o Panache e o que ele faz com Markdown?

Panache é um language server, formatador e linter para Markdown, Quarto e R Markdown, escrito em Rust com um parser de árvore sintática concreta (CST) sem perdas. Ele oferece um único CLI que pode formatar um arquivo no lugar, auditar problemas de formatação, corrigi-los automaticamente e rodar um servidor LSP para integração com o editor. Também suporta executar formatadores e linters externos (como Prettier, ruff ou black) nos blocos de código dentro dos seus documentos Markdown.

Por que eu formataria e auditaria o Markdown que capturo de um thread do X?

Um thread capturado é uma cópia fiel, não uma versão polida: os posts chegam com larguras de linha inconsistentes, estilos de lista misturados, parágrafos com quebras irregulares e blocos de código nunca formatados. Essa fonte bagunçada é difícil de editar e republicar. Rodar um formatador normaliza as quebras, reflui parágrafos para a largura de linha que você escolher e corrige automaticamente listas e espaçamentos, transformando o Markdown em um arquivo-fonte limpo e profissional.

O Panache é uma alternativa ao Prettier ou ao mdformat?

O Panache se sobrepõe a essas ferramentas, mas é construído em torno da sintaxe de Quarto, Pandoc e R Markdown, que o Prettier e o mdformat não lidam completamente (por exemplo, divs com cercas e certa sintaxe de tabela). Ele também adiciona um language server LSP, um linter integrado com auto-correção, formatação recursiva por glob e formatadores externos de blocos de código. Para Markdown simples, você costuma usá-lo como substituto direto; para documentos Quarto ou R Markdown, ele lida com sintaxe que as ferramentas mais antigas não suportam.

Posso rodar o Panache em threads capturados automaticamente antes de republicar?

Sim. O Panache tem um hook de pre-commit dedicado e uma GitHub Action, permitindo formatar e auditar cada arquivo Markdown capturado automaticamente na CI ou antes de cada commit. Você também pode chamá-lo em um loop de shell de uma linha sobre um diretório de threads capturados, ou enviar um único arquivo pelo stdin com panache format. Isso facilita manter cada thread capturado limpo sem precisar rodar manualmente.

MRDown 2026: Verifique Redações de IA Antes de Republicar

5 de Setembro de 2026 · ThreadGrab

A forma mais comum de um thread do X reaproveitado dar errado não é o thread. É a reescrita. Você captura um thread público como Markdown, entrega-o a uma IA para reformatar como um X Article ou um post do LinkedIn, e o modelo muda silenciosamente um número, omite uma ressalva ou transforma uma afirmação em outra mais forte. A saída parece perfeita. Só que não é mais o que o autor original disse.

O MRDown é um visualizador e editor de Markdown nativo do macOS, licenciado como MIT e grátis, que nasceu do incômodo de um desenvolvedor com os arquivos .md que o Claude Code vive gerando. Sua peça central é uma capacidade que quase nenhum app de Markdown entrega: ele mostra a você o diff do que a sua IA acabou de reescrever. A versão 1.14.0 chegou em 2 de setembro de 2026. Para quem reaproveita threads capturados com ajuda de IA, o MRDown é melhor entendido não como mais um editor, mas como a verificação contra desvio de sentido entre uma redação de IA e uma republicação pública.

Resumo rápido: o MRDown (github.com/MR-TABATA/MRDown, v1.14.0, 2 de setembro de 2026) mantém uma versão datada a cada salvamento ou reescrita — inclusive por um agente externo — e mostra quaisquer duas versões lado a lado com apenas as palavras alteradas marcadas. No fluxo capturar → reescrever com IA → verificar → republicar, ele é o passo que detecta desvio de sentido silencioso antes de você publicar. Grátis, MIT, macOS 10.15+ (Apple Silicon e Intel).

Por que a reescrita é onde o reaproveitamento quebra

O ThreadGrab transforma um thread público em Markdown para você editar, reembalar ou republicar em outro lugar. No instante em que você cola esse Markdown num composer de IA e pede uma versão "mais envolvente", perde a capacidade de ver o que de fato mudou. Os modelos não dizem qual frase reformularam e qual reforçaram. Sem um diff, todo thread reaproveitado é publicado na fé.

A falha raramente é dramática. Um original que diz "aproximadamente metade dos testadores beta relatou carregamento mais rápido" vira "a maioria dos usuários beta viu carregamento drasticamente mais rápido". O sentido não inverteu — ele derrapou. Para conteúdo arquivado e atribuído, deriva é pior que exclusão: a versão errada agora carrega o nome do autor original.

O que o MRDown realmente faz

O MRDown começou (nas palavras do próprio autor) como um projeto de duas horas para visualizar arquivos .md sem abrir um editor pesado. Virou um visualizador-e-editor completo com um diferencial. Os recursos que importam para um fluxo de reaproveitamento:

  • Histórico de versões com diffs. Cada salvamento — e cada reescrita vinda de fora do app — guarda silenciosamente uma versão datada. O painel de histórico põe quaisquer duas versões lado a lado; só as palavras que diferem são marcadas, e trechos inalterados são recolhidos.
  • Resgate de conflito em três colunas. Se algo altera o arquivo no disco enquanto você tem edições não salvas, o MRDown mostra três colunas — último salvamento, o que está no disco, suas edições — e marca apenas as linhas que você e o outro escritor alteraram. Nada é sobrescrito ou perdido silenciosamente.
  • O HEAD do Git entra na lista. Num repositório Git, sua versão commitada aparece no mesmo histórico, então o diff contra o que você commitou por último está a um clique. Git é totalmente opcional.
  • Compare quaisquer dois arquivos. ⌘⇧D faz o diff de dois documentos lado a lado na mesma visão — inclusive dois arquivos .docx que o MRDown abre como Markdown.

Para uma ferramenta que as pessoas usam quando um agente está editando seus arquivos, esse último ponto importa: o MRDown não sabe qual aplicativo escreveu uma mudança (o macOS não registra isso), mas registra que algo mudou o arquivo no disco enquanto você não olhava, que é exatamente a falha que a maioria dos editores esconde.

O fluxo capturar → verificar

Este é o fluxo em que o MRDown se encaixa. Ele parte do princípio de que você já capturou o thread como Markdown.

  1. Capture. Guarde o thread público como Markdown com a API do ThreadGrab ou uma ferramenta do seu stack de arquivo. Salve-o numa pasta local, de preferência dentro de um repositório Git.
  2. Reescreva com uma IA. Aponte seu composer de IA para o arquivo Markdown e peça o rascunho reaproveitado. Diga ao modelo para editar no lugar ou salvar num novo arquivo de rascunho.
  3. Compare a redação no MRDown. Abra o painel de histórico (ícone de relógio) e compare o salvamento pré-IA contra o pós-IA, ou compare os dois arquivos de rascunho com ⌘⇧D. Só as palavras alteradas acendem, então um número trocado ou um "não" removido fica visível em segundos.
  4. Confirme ou rejeite cada mudança. Restaure qualquer versão em um clique, sem destruir nada — nada é gravado até você salvar. Marque as fronteiras de afirmação que você não quer entregar a uma IA.
  5. Republicue. Exporte o Markdown verificado para HTML (⌘⇧E) ou cole-o no seu composer de X Article / LinkedIn / newsletter com confiança.

O passo que a maioria pula é o terceiro. Adicionar uma checagem de diff entre a redação da IA e a fonte transforma uma republicação às cegas numa revisada — sem precisar ler dois documentos longos linha por linha.

Checagem de versão lado a lado em código

Se preferir verificar no terminal, a mesma lógica é um único comando de diff. Estes pares de comandos são usados nos dois lugares:

# works on Linux and macOS; USERNAME is the X handle to archive
curl -s https://threadgrab.com/api/profile/USERNAME \
  | jq -r '.[] | "# \(.author)\n\n\(.text)\n---"' > original.md

# after the AI writes a repurposed draft, spot every drifted line
diff -u original.md repurposed.md

O MRDown dá o mesmo sinal em forma visual — e, ao contrário de um diff de terminal, ele sabe que uma mudança cosmética de palavras e uma que altera o sentido são ambas apenas "linhas alteradas", então cabe a você ler cada palavra destacada.

O lado de autoria que o criou

O MRDown é open-core: o repositório é o app inteiro, MIT, e continua MIT. O autor afirmou que os recursos pagos a vir — IA explicando um diff, busca em todo o projeto, remotes autenticados — viverão num repositório pago separado. Para quem reaproveita, os fatos verificados em que você pode confiar hoje: a edição no lugar troca a visão de leitura por um editor, o arquivo no disco nunca é reescrito pelo próprio app (o que mantém o diff honesto), e ele renderiza tabelas, código, Mermaid, matemática KaTeX e listas de tarefas. É assinado e notarizado com um Apple Developer ID e roda em macOS 10.15 ou posterior.

Limitações que vale conhecer

  • Binários só para macOS. Ele é construído com Tauri e poderia, em tese, rodar no Windows, mas nenhum build Windows é distribuído e não há certificado de assinatura de código para Windows.
  • Ele não sabe qual app mudou o arquivo. O macOS não registra isso. O MRDown sabe que uma mudança aconteceu no disco, não que foi o Claude — por isso um passo de diff dedicado importa para reaproveitamento com forte atribuição.
  • O diff é seu julgamento. O MRDown marca palavras alteradas; ele não julga se uma mudança inverte o sentido. Para uma afirmação factual à qual você vai anexar o nome de um autor, leia você mesmo cada palavra destacada.
  • Projeto em estágio inicial. O ritmo rápido de lançamentos (seis versões em agosto até a v1.14 em 2 de setembro) significa que os recursos mudam depressa; verifique o comportamento atual no app antes de apostar um fluxo semanal nele.

Mantenha a proveniência com o conteúdo

O hábito do threadgrab combina naturalmente com o MRDown. Capture uma vez, mantenha o Markdown original como fonte de verdade e nunca deixe uma reescrita de IA ser a única versão na pasta. Quando você guarda original.md e repurposed.md juntos, o diff é sempre reproduzível — exatamente o que você quer se um thread republicado for contestado quanto à atribuição.

# keep both versions in one folder so the diff stays reproducible
mkdir -p ./thread-2026-09-05 && cd ./thread-2026-09-05
mv ~/original.md ./original.md
# hash both; store the hashes with the files
sha256sum original.md repurposed.md > checksums.txt

Arquive o original. Compare a reescrita. Depois publique com a fonte ao lado da versão que leva o seu nome.

FAQ

Por que não simplesmente ler com atenção a saída da IA? Porque uma leitura atenta de um documento polido é exatamente o que permite a uma reescrita confiante e gramaticalmente limpa esconder uma afirmação alterada. Um diff força a comparação contra a fonte; sua atenção vai para as palavras que de fato se moveram, não para o quão bem o texto inteiro soa.

O que é o MRDown em uma linha?

Um visualizador e editor de Markdown para macOS, grátis e MIT, cujo recurso de assinatura é mostrar a você o diff do que sua IA acabou de reescrever — cada salvamento e cada reescrita externa mantém uma versão datada que você pode comparar lado a lado.

O MRDown substitui o ThreadGrab?

Não. O ThreadGrab captura um thread público do X como Markdown; o MRDown não busca nada na web. O MRDown fica um passo depois no fluxo — depois que você tem o Markdown e antes de republicar — como a camada de verificação entre uma redação de IA e a versão que você publica.

Como o MRDown sabe que minha IA reescreveu o arquivo?

Ele não sabe qual app fez isso — o macOS não registra. Ele sabe que o arquivo no disco mudou enquanto uma versão estava aberta, faz um snapshot da versão no disco no instante em que é vista e oferece uma visão de três colunas (último salvamento / no disco / suas edições) quando você e um escritor externo alteram linhas sobrepostas.

O MRDown é uma boa ferramenta de diff para threads reaproveitados mesmo sem usar Git?

Sim. O histórico de versões é embutido e vive no diretório de dados do app, então nunca polui seus arquivos nem seu repositório Git. Git é opcional — mas se seu Markdown está num repositório, o HEAD commitado entra na mesma lista de histórico, dando a você o diff contra o commit em um clique.

O MRDown é mesmo grátis e continua grátis?

O repositório é o MRDown, inteiramente MIT, e seu autor afirmou que continua MIT — é open-core. Os recursos pagos planejados (IA explicando um diff, busca em todo o projeto, remotes autenticados como GitHub) serão desenvolvidos num repositório separado e não serão removidos do app grátis.

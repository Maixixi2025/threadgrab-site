Shadowbroker MCP 2026: Dasbor OSINT untuk Kreator Sosial

Beranda › Blog › Dasbor OSINT Shadowbroker MCP

3 Juli 2026 · 11 menit baca · oleh ThreadGrab

Jika Anda menulis untuk X Articles, Bluesky long-form, dan LinkedIn Newsletter, Anda sudah tahu rasanya: percakapan paling menarik tersebar di tiga platform, tiga feed, dan tiga permukaan discovery yang berbeda. Melacaknya di satu tab browser berarti berpindah konteks sepanjang hari. Melacaknya di tiga tab berarti kehilangan 40% dari yang ingin Anda tinjau ulang.

Bagaimana jika satu server MCP bisa menarik postingan X, thread Bluesky, pembaruan LinkedIn, feed RSS, rilis GitHub, dan 10+ sumber lainnya ke dalam satu dasbor real-time — dan membiarkan agen AI Anda (Claude Code, Codex CLI, Cursor) mengkuerinya sesuai kebutuhan?

Itulah yang dilakukan Shadowbroker. Ini adalah dasbor OSINT (open-source intelligence) bertenaga MCP tahun 2026 yang dibangun oleh satu developer (BigBodyCobain di GitHub) yang membungkus 15+ sumber sosial, kode, dan berita di balik antarmuka MCP terpadu. Untuk kreator konten sosial, ini adalah implementasi referensi nyata dari sesuatu yang sudah kami bahas selama berbulan-bulan: gunakan MCP untuk memecah silo platform.

Hari ini kita akan membahas apa itu Shadowbroker, mengapa penting untuk penulis X / Bluesky / LinkedIn, bagaimana integrasi MCP benar-benar bekerja di balik layar, dan bagaimana mengadaptasi pola yang sama untuk alur kerja kreator Anda sendiri — bahkan jika Anda tidak ingin menginstal Shadowbroker itu sendiri.

Apa yang Sebenarnya Dilakukan Shadowbroker

Shadowbroker pada dasarnya adalah agregator tipis. Setiap sumber yang ditariknya dibungkus sebagai alat Model Context Protocol (MCP) — protokol yang sama yang menggerakkan fitur penggunaan alat di Claude Code, Codex CLI, dan Cursor. Setelah berjalan, ia mengekspos antarmuka seragam di mana agen AI Anda bisa memanggil sesuatu seperti:

search_x(query="AI agents social workflow", limit=20)
list_bluesky_feed(handle="threadgrab.bsky.social", limit=10)
fetch_linkedin_post(url="https://linkedin.com/posts/...")
read_rss(url="https://hnrss.org/newest", limit=15)

Setiap fungsi tersebut adalah alat MCP nyata yang didaftarkan oleh server Shadowbroker. Agen AI di editor Anda tidak butuh integrasi API kustom per platform — cukup panggil alatnya dan dapatkan respons terstruktur kembali.

15+ sumber yang saat ini dibungkus Shadowbroker (menurut README proyek per Juli 2026) meliputi:

  • X (Twitter) — pencarian, timeline pengguna, ambil postingan
  • Bluesky — baca feed, cari postingan, lookup profil via API publik AT Protocol
  • LinkedIn — terbatas (bergantung pada URL postingan publik, bukan autentikasi sesi penuh)
  • RSS / Atom — parser feed generik untuk URL apa pun
  • Hacker News — cerita teratas, komentar, pencarian via Algolia
  • GitHub Releases — feed rilis per repositori
  • Reddit — subreddit + pencarian via API JSON publik
  • Mastodon — baca timeline federasi
  • YouTube — ambil transkrip publik (tanpa autentikasi)
  • arXiv — pencarian paper (untuk penulis komentar sosial akademis)
  • PubMed — pencarian paper biomedis
  • Wikipedia — artikel + ringkasan
  • OpenStreetMap — geocoding
  • Weather — Open-Meteo (tanpa API key)
  • Kutipan saham — endpoint publik terbatas

Daftarnya adalah campuran lintas domain yang disengaja: platform sosial, berita dev, penelitian akademis, referensi faktual. Itulah ethos OSINT — memperlakukan seluruh web terbuka sebagai permukaan yang bisa dikueri.

Mengapa Pola Ini Penting untuk Kreator Konten Sosial

Jika Anda menulis untuk X Articles, Bluesky long-form, atau LinkedIn Newsletter, alur kerja nyata Anda bukanlah "posting ke platform X". Melainkan:

  1. Menemukan apa yang orang bicarakan sekarang (fase riset)
  2. Menyaring apa yang worth untuk tulisan panjang (fase kurasi)
  3. Mendraft respons / sudut pandang (fase penulisan)
  4. Cross-post hasilnya ke beberapa platform dengan format spesifik platform (fase distribusi)

Langkah 1 adalah tempat pola Shadowbroker bersinar. Saat ini, kebanyakan kreator menjalankan fase discovery di browser dengan 12 tab terbuka. Setiap tab adalah UI terpisah, sesi autentikasi terpisah, konteks mental terpisah. Percakapan yang sama di X, Bluesky, dan LinkedIn terlihat seperti tiga event berbeda.

Apa yang dilakukan Shadowbroker — dan apa yang mulai dilakukan ekosistem MCP yang lebih luas — adalah mengonsolidasikan discovery itu menjadi satu antarmuka yang bisa dikueri agen AI Anda. Alih-alih berpindah tab, Anda mengetik di Claude Code atau Cursor:

Use the shadowbroker MCP tools to find the 5 most-discussed
posts about "agent reliability" across X, Bluesky, and LinkedIn
in the last 48 hours. Group by sentiment and return URLs.

Agen memanggil alat MCP yang relevan, mendapatkan respons terstruktur, dan memberi Anda satu ringkasan. Anda tetap di editor sepanjang waktu.

Setup: Menjalankan Shadowbroker Secara Lokal

Shadowbroker adalah proyek open-source. Setup-nya sengaja ringan: Python 3.11+, beberapa paket, dan klien MCP (Claude Code, Codex CLI, atau Cursor). Menurut README GitHub:

git clone https://github.com/BigBodyCobain/Shadowbroker.git
cd Shadowbroker
pip install -r requirements.txt

# Configure your MCP client (Claude Code example)
# In ~/.claude.json or your project's .mcp.json:
{
  "mcpServers": {
    "shadowbroker": {
      "command": "python",
      "args": ["/path/to/Shadowbroker/server.py"]
    }
  }
}

Untuk pengguna Claude Code, JSON itu masuk ke .mcp.json proyek Anda. Untuk Codex CLI, masuk ke ~/.codex/config.toml di bawah [mcp_servers.shadowbroker]. Untuk Cursor, Anda konfigurasi di Settings › MCP › Add new global MCP server.

Tidak ada image Docker, tidak ada pendaftaran SaaS, tidak ada pertukaran API key untuk kebanyakan sumber. X adalah pengecualian sebagian: Shadowbroker bisa menggunakan API pencarian publik tanpa autentikasi untuk kueri terbatas, tapi penggunaan berat akan membutuhkan bearer token (yang didokumentasikan proyek di README).

Ide Inti: Memperlakukan Web Terbuka Sebagai Satu Permukaan yang Bisa Dikueri

Yang membuat Shadowbroker menarik bukan daftar sumbernya — developer mana pun bisa membungkus 15 API HTTP. Yang menarik adalah proyek ini berkomitmen pada permukaan MCP yang seragam. Agen tidak perlu tahu apakah sedang memanggil X, Bluesky, Hacker News, atau arXiv. Nama alat dan argumennya dinormalisasi.

Ini adalah insight yang sama yang menggerakkan banyak pengembangan MCP di 2026: nilai MCP bukan protokolnya itu sendiri, melainkan normalisasinya. Tanpa normalisasi, agen butuh alat kustom per platform. Dengan normalisasi, agen bisa merangkai kueri lintas platform tanpa kode tambahan.

Untuk kreator konten sosial, itu berarti prompt agen yang sama yang bertanya "apa yang trending di X" juga bisa bertanya "bagaimana pandangan akademis tentang ini" dengan mengganti nama alatnya. Agen itu sendiri tidak perlu tahu bahwa satu alat mengenai X dan yang lain mengenai arXiv. Cukup panggil dan sintesiskan.

Walkthrough Setup: Alur Kerja Kreator yang Konkret

Mari kita telusuri bagaimana sesi kreator nyata terlihat dengan Shadowbroker berjalan. Skenario: Anda sedang menulis postingan panjang di Bluesky tentang alat keandalan agen AI dan ingin menjadikannya referensi diskusi lintas platform saat ini.

Langkah 1: Discovery lintas platform. Di editor Anda, Anda bertanya:

Use the shadowbroker MCP server to gather:

1. The top 5 X posts from the last 72 hours matching
   "agent reliability" or "agent eval"
2. The top 5 Bluesky posts from the last 72 hours with the
   same keywords
3. The top 3 Hacker News threads from the last 7 days
4. The 2 most recent arXiv papers on the topic

Return as a single table with platform, URL, summary, and
engagement count.

Di balik layar, agen memanggil 4 alat MCP, yang masing-masing mengenai sumber berbeda. Responsnya adalah tabel ternormalisasi. Seluruh fase discovery memakan waktu kurang dari satu menit, dan Anda tidak pernah keluar dari editor.

Langkah 2: Cross-reference dan pull kutipan. Anda memilih sumber paling menarik dari tabel. Lalu:

For each row in the discovery table, fetch the full text of
the top post / thread / paper. For X and Bluesky, pull the
post body. For HN, pull the top 3 comments. For arXiv, pull
the abstract. Save the result to ./research-brief.md.

Sekarang Anda punya brief riset dalam markdown yang bisa dibaca, dianotasi, dan di-draft dari. Brief-nya portabel: itu hanya sebuah file. Anda bisa commit, share, atau feed ke LLM berbeda untuk draf sebenarnya.

Langkah 3: Draft. Di sinilah Anda, penulis manusia, mengambil alih. Discovery dan pull kutipan adalah mekanis. Sintesis — memilih hook, menemukan sudut, memilih struktur — adalah bagian yang tidak bisa dilakukan MCP untuk Anda. Tapi input untuk sintesis itu sekarang richer satu order of magnitude, karena Anda melihat 15 sumber dalam 60 detik bukan 3 sumber dalam 30 menit.

Langkah 4: Cross-post dengan format spesifik platform. Setelah Anda punya drafnya, fase distribusi adalah cerita MCP-nya sendiri (kami membahasnya di artikel X Hosted MCP kami dan artikel OpenRouter MCP server). Shadowbroker menangani ingesti; X / OpenRouter MCP menangani routing dan posting.

Bagaimana Shadowbroker Dibandingkan dengan Server MCP Lain

Shadowbroker adalah satu dari daftar server MCP yang terus bertambah yang menargetkan kreator konten sosial. Lanskap 2026 punya tiga archetype utama:

ServerFokusSumberCocok Untuk
Shadowbroker OSINT (ingesti) 15+ (X, Bluesky, HN, arXiv, GitHub, RSS, …) Discovery lintas platform, riset, pengumpulan fakta
OpenRouter MCP Routing LLM (penulisan) 100+ model via OpenRouter Draf multi-model, perbandingan model-A-vs-B
X Hosted MCP Distribusi Hanya API X (Twitter) Posting langsung ke X dari agen

Tiga server MCP ini komplementer, bukan kompetitif. Shadowbroker adalah lapisan ingesti upstream. OpenRouter MCP adalah lapisan routing menengah (model mana yang menulis draf). X Hosted MCP adalah lapisan distribusi downstream (bagaimana post benar-benar sampai ke timeline). Stack kreator serius di 2026 kemungkinan akan menjalankan ketiganya — masing-masing memecahkan masalah berbeda.

Untuk pembaca kami yang sudah menggunakan OpenRouter MCP untuk draf multi-model, Shadowbroker mengisi bagian yang hilang di sisi ingesti. Anda tidak perlu lagi keluar dari editor untuk melakukan discovery.

Keterbatasan dan Peringatan yang Jujur

Shadowbroker adalah proyek satu developer. Itu punya implikasi:

  • Rate limit X: API pencarian publik X tanpa bearer token sangat rate-limited. Penggunaan berat akan butuh autentikasi, yang berarti API key yang harus Anda kelola.
  • Cakupan LinkedIn: LinkedIn tidak mengekspos API publik yang bersih. Alat LinkedIn Shadowbroker bekerja pada URL post publik (Anda tempel URL, ia ambil halaman), bukan pada pencarian sembarang. Jika Anda butuh monitoring LinkedIn yang luas, ini adalah gap.
  • Jumlah sumber dangkal, bukan dalam: 15+ sumber terdengar banyak, tapi kedalaman per sumber terbatas. Anda mendapat top post / top thread / top paper, bukan firehose penuh. Untuk kebanyakan alur kerja kreator, itu cukup. Untuk ingesti skala redaksi, Anda ingin stack berbeda.
  • Tanpa persistensi auth: Beberapa sumber (GitHub, Reddit) bekerja lebih baik dengan auth token. Shadowbroker membacanya dari env var; jika token Anda kadaluarsa, alatnya menurun secara diam-diam.

Tidak ada yang jadi dealbreaker untuk target audiens. Poin Shadowbroker bukanlah menjadi platform OSINT redaksi. Poinnya adalah menjadi asisten riset kreator — kecil, cepat, lokal, tanpa pendaftaran.

Membangun Milik Anda: Polanya, Bukan Proyeknya

Takeaway terbesar dari Shadowbroker bukanlah proyeknya itu sendiri. Melainkan polanya: bungkus N API HTTP sebagai alat MCP, normalisasi permukaannya, ekspos ke agen Anda. Anda bisa melakukan ini dengan 20 baris Python dan 2 jam kerja, bahkan jika tidak menggunakan Shadowbroker.

Contoh minimal untuk satu sumber (Bluesky) akan terlihat seperti:

# my_social_mcp.py — a minimal MCP server for one platform
from mcp.server import Server
from mcp.types import Tool
import httpx

app = Server("my-social")

@app.tool()
async def search_bluesky(query: str, limit: int = 10) -> list:
    """Search recent Bluesky posts for a query string."""
    url = "https://public.api.bsky.app/xrpc/app.bsky.feed.searchPosts"
    r = httpx.get(url, params={"q": query, "limit": limit}, timeout=10)
    return r.json().get("posts", [])

Server 10-baris itu adalah server MCP nyata. Wire ke Claude Code, dan Anda bisa memanggil search_bluesky dari agen Anda. Pola yang sama bekerja untuk X (dengan bearer token), Reddit (JSON publik), HN (Algolia), dan kebanyakan feed RSS. Anda tidak butuh mega-server 15-sumber untuk mendapat 80% nilainya.

Mulai dengan 1-2 sumber yang benar-benar Anda gunakan untuk riset. Tambahkan lebih saat alur kerja terbukti. Ekosistem MCP berada di puncak saat alat yang Anda bangun sesuai dengan pekerjaan yang benar-benar Anda lakukan, bukan pekerjaan yang ditebak oleh dasbor generalis bahwa Anda lakukan.

FAQ: Pertanyaan Umum dari Kreator Sosial

Apakah Shadowbroker gratis?

Ya. Proyek ini berlisensi MIT di GitHub. Anda menjalankannya secara lokal; tidak ada layanan hosted, tidak ada pendaftaran, tidak ada batas penggunaan. Satu-satunya biaya adalah API key yang Anda bawa sendiri (mis. bearer token X jika ingin melewati rate limit publik).

Apakah saya harus pakai Claude Code untuk mendapat manfaat dari Shadowbroker?

Tidak. Klien apapun yang kompatibel dengan MCP bisa dipakai. Tiga besar di 2026 adalah Claude Code, OpenAI Codex CLI, dan Cursor. Ketiganya bisa mendaftarkan Shadowbroker sebagai server MCP. Lapisan agennya bisa saling dipertukarkan.

Bagaimana Shadowbroker berbeda dari Zapier atau IFTTT untuk agregasi sosial?

Zapier dan IFTTT adalah otomatisasi berbasis trigger: post baru yang cocok dengan aturan menyebabkan aksi downstream. Shadowbroker adalah ingesti yang bisa dikueri agen: agen meminta digest sesuai permintaan, real-time, dengan hasil terstruktur. Model mentalnya berbeda. Zapier memindahkan data antar app. Shadowbroker memberi LLM pandangan terpadu tentang web terbuka.

Bisakah saya menggunakan Shadowbroker untuk posting, atau hanya baca?

Hanya baca. Shadowbroker adalah alat ingesti / riset. Untuk posting, lapisi dengan server MCP berbeda — X Hosted MCP untuk X, API Bluesky untuk Bluesky (tulis wrapper MCP tipis Anda sendiri), dan serupa untuk LinkedIn. Kami membahas sisi X di artikel X Hosted MCP kami.

Bagaimana cara menghindari rate limit X?

Dapatkan bearer token dari portal developer X. Shadowbroker membacanya dari env var X_BEARER_TOKEN. Tier gratis memberi 100 bacaan per 15 menit; tier bayar dasar memberi lebih. Untuk kebanyakan sesi riset kreator, itu sudah lebih dari cukup.

Apakah ada versi hosted dari Shadowbroker?

Belum per Juli 2026. Proyek ini secara eksplisit local-first. Maintainer mencatat minat pada tier hosted tapi belum commit. Jika Anda butuh OSINT tim bersama, Anda akan men-deploy Shadowbroker di infrastruktur sendiri (VM kecil sudah cukup).

Apakah Shadowbroker bekerja dengan feed kustom Bluesky?

Sebagian. Alat Bluesky bisa mengambil feed profil publik (mis. threadgrab.bsky.social) dan bisa mencari di firehose publik. Feed kustom (yang algoritmik yang dikomposisi pengguna) membutuhkan URI feed sendiri dan belum dibungkus. Untuk kebanyakan kreator, feed publik adalah yang Anda inginkan pula.

Penutup: Satu Pola, Banyak Sumber, Nol Perpindahan Tab

Shadowbroker adalah salah satu contoh paling jelas di 2026 dari pola MCP yang membayar untuk kreator individu. Janji MCP selalu: satu protokol, banyak alat, ramah agen. Shadowbroker adalah realisasi paling konkret dari janji itu untuk kreator konten sosial — 15+ sumber, satu permukaan ternormalisasi, tanpa perpindahan tab.

Anda tidak harus menginstal Shadowbroker untuk mendapat manfaat dari polanya. Takeaway-nya: bungkus web terbuka dalam alat MCP, ekspos ke agen Anda, dan biarkan agen melakukan discovery lintas platform dalam hitungan detik. Apakah Anda membangun server 1-sumber sendiri atau menjalankan mega-server 15-sumber, pembukaan produktivitasnya sama.

Untuk pembaca ThreadGrab secara spesifik, pasangan alaminya adalah Shadowbroker untuk ingesti + OpenRouter MCP untuk draf multi-model + X Hosted MCP untuk distribusi. Stack tiga-lapisan itu mencakup loop kreator lengkap dari riset ke publikasi, semua dari dalam editor Anda, semua tanpa meninggalkan keyboard untuk browser.

Baca bagian terkait untuk lapisan stack lainnya: OpenRouter MCP untuk draf multi-model, X Hosted MCP untuk posting langsung oleh agen, dan artikel Caliper AI agent reliability kami untuk lapisan eval / drift tracking yang menutup loop.

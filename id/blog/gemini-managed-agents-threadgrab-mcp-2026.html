Gemini Managed Agents + ThreadGrab MCP 2026

16 Juli 2026 · 11 min read · Guide

Apa yang berubah pada 7 Juli 2026

API Gemini Google secara diam-diam menambahkan dua hal yang penting bagi kreator konten sosial: Managed Agents — tugas latar belakang jangka panjang yang bertahan antar giliran — dan dukungan MCP jarak jauh, kemampuan agen untuk memanggil server Model Context Protocol yang di-hosting dan tidak berjalan dalam proses yang sama. Sampai minggu lalu, agen Gemini hanya dapat memanggil server MCP lokal atau alat milik Google. Sekarang agen yang berjalan di cloud Gemini dapat membuka koneksi jaringan ke endpoint MCP jarak jauh, mendaftar alat yang dieksposnya, dan memanggilnya melalui HTTP seperti panggilan alat lokal.

Itu terdengar teknis, tetapi efek praktisnya singkat. Jika Anda menjalankan server MCP publik — dan ThreadGrab sudah punya satu sejak Maret — agen Gemini sekarang dapat menjangkaunya. Agen membaca timeline X, thread, dan kiriman newsletter LinkedIn Anda melalui MCP ThreadGrab, menyusun draf balasan, meminta Anda mengonfirmasi, lalu memposting balasan. Tanpa kode perekat. Tanpa langkah OAuth per alat. Alur yang sama yang bekerja untuk Claude Code bulan lalu kini bekerja di dalam loop agen Gemini.

Apa yang sebenarnya diekspos server MCP ThreadGrab

ThreadGrab menjalankan server MCP hosted di https://threadgrab.com/api/mcp. Ia mengekspos delapan alat, dikelompokkan dalam tiga grup. Alat baca (read_post, read_thread, search_timeline) mengembalikan Markdown, bukan JSON, sehingga agen dapat menyerap konten secara langsung tanpa langkah parsing. Alat tulis (draft_reply, draft_post) mengembalikan objek draf dengan token konfirmasi — agen harus memanggil confirm_post sebelum draf dipublikasikan, yang berarti manusia tetap berada di loop pada setiap pos keluar. Alat arsip (archive_thread, archive_post) mempertahankan konten di arsip ThreadGrab privat yang dapat diaudit kreator nanti.

Server ini dilindungi OAuth. Anda mendaftar akun ThreadGrab, membuat token MCP, dan mengirimkannya sebagai header bearer. Token diberi scope — token hanya-baca tidak dapat memanggil alat tulis; token platform tunggal hanya bekerja di X atau hanya di Bluesky. Ini adalah model scope yang sama yang sudah diterapkan klien MCP, sehingga Claude Code dan Cursor menanganinya tanpa perubahan konfigurasi.

Bagaimana agen Gemini baru dibandingkan dengan Claude Code, Cursor, dan Windsurf

Keempatnya kini dapat mengonsumsi server MCP jarak jauh, tetapi mereka menangani loop agen secara berbeda. Claude Code dan Windsurf berjalan di terminal atau editor Anda — Anda menonton setiap panggilan alat, menyetujui yang destruktif, dan loop berakhir saat Anda menutup sesi. Managed Agents Gemini berjalan di cloud Google dan bertahan antar giliran: Anda memulai agen pada Senin, ia menjalankan pekerjaan latar belakang, dan Anda mengecek lagi pada Rabu. Itu改变了 jenis pekerjaan yang masuk akal.

Baris bawah adalah yang terpenting. Managed Agents Gemini adalah loop agen hosted pertama dengan dukungan MCP jarak jauh kelas satu dan status persisten. Jika pekerjaan Anda adalah “pantau percakapan Bluesky selama 48 jam, rangkum 20 pos teratas, dan susun tiga varian balasan untuk tinjauan saya”, Managed Agents Gemini adalah satu-satunya dari keempatnya yang menanganinya tanpa Anda harus terus mengawasinya.

Menghubungkan ThreadGrab ke agen Gemini dalam lima langkah

Pengaturan memakan waktu sekitar sepuluh menit. Anda membutuhkan akun ThreadGrab, kunci API Gemini dengan beta Agents diaktifkan, dan instalasi gcloud yang berfungsi.

1. Buat token MCP ThreadGrab

Buka threadgrab.com, masuk, buka Pengaturan → Token MCP, dan klik Token baru. Pilih scope yang Anda inginkan — read+write:x memungkinkan agen membaca timeline dan memposting balasan ke X. Beri nama token dengan sesuatu yang akan Anda kenali nanti, seperti gemini-agent-senin. Salin token bearer; ThreadGrab menampilkannya sekali.

2. Aktifkan beta Gemini Agents

Endpoint Agents digate oleh header beta. Kirim permintaan satu kali ke POST https://generativelanguage.googleapis.com/v1beta/agents dengan x-goog-api-key diisi, dan body kosong. Respons 200 berarti proyek Anda masuk. Jika Anda mendapat 403, bergabunglah dengan daftar tunggu di aistudio.google.com → Agents.

3. Daftarkan server MCP ThreadGrab

Kirim payload konfigurasi ke API Gemini Agents:

{
  "name": "threadgrab",
  "type": "remote_mcp",
  "endpoint": "https://threadgrab.com/api/mcp",
  "auth": {
    "type": "bearer",
    "token_env": "THREADGRAB_MCP_TOKEN"
  },
  "tools": ["read_post", "read_thread", "search_timeline", "draft_reply", "confirm_post", "archive_thread"]
}

Simpan server_id yang dikembalikan — Anda akan mereferensikannya di setiap definisi agen.

4. Definisikan agen

Buat agen yang tahu kapan memanggil ThreadGrab. System prompt harus memberi tahu agen bahwa threadgrab.search_timeline adalah alat baca utama dan bahwa confirm_post adalah satu-satunya jalur untuk mempublikasikan.

{
  "name": "x-thread-monitor",
  "model": "gemini-2.5-pro",
  "servers": ["threadgrab"],
  "system_prompt": "Anda memantau thread X. Gunakan threadgrab.search_timeline untuk menemukan pos baru, rangkum 3 teratas setiap 6 jam, dan gunakan draft_reply untuk hal yang memerlukan balasan. Jangan pernah memanggil confirm_post tanpa persetujuan eksplisit pengguna."
}

5. Mulai agen dan atur interval polling

Kirim definisi agen untuk memulainya. Managed Agents Gemini menerima kolom cron yang menjadwalkan seberapa sering loop agen bangun. Mengaturnya ke 0 */6 * * * membangunkan agen setiap enam jam — irama yang wajar untuk pekerjaan pemantauan sosial jangka panjang.

Tiga pekerjaan konkret yang berubah bagi kreator

1. Pemantauan jangka panjang menjadi satu agen

Sebelumnya, “pantau thread X ini selama 48 jam” berarti cron job plus antrean plus langkah perangkuman terpisah. Dengan Managed Agent Gemini, Anda menentukan pekerjaan sekali. Agen melakukan polling ThreadGrab sesuai jadwalnya, mempertahankan status percakapan antar giliran, dan menulis rangkumannya kembali ke arsip ThreadGrab Anda di akhir setiap siklus. Anda mengecek arsip saat ingin pembaruan status, bukan saat agen memutuskan memberi tahu Anda.

2. Draf terjadwal tanpa kehilangan pengecekan manusia

Agen dapat menyusun draf setiap Senin pukul 9 pagi, tetapi confirm_post tetap memerlukan klik pengguna. Itu mempertahankan janji manusia-di-loop. Perbedaan dari cron job biasa adalah konteksnya: agen mengingat draf minggu lalu, mengetahui apa yang Anda setujui dan apa yang Anda tolak, dan memperbaiki draf berikutnya.

3. Pengarsipan lintas-platform sebagai efek samping

Setiap panggilan baca dan tulis yang dilakukan agen diarsipkan secara otomatis oleh ThreadGrab. Dua bulan kemudian, Anda dapat menarik ekspor bersih dari setiap pos yang dibaca agen dan setiap balasan yang Anda setujui. Ini adalah sudut pandang provenance-first yang paling penting ketika agen AI melakukan pekerjaan atas nama Anda — Anda dapat membuktikan apa yang dilihat agen dan apa yang Anda setujui.

Bagaimana ThreadGrab muat di antara Gemini dan platform sosial

ThreadGrab tidak bersaing dengan Managed Agents Gemini — ia berada di belakangnya. Gemini menangani loop agen, pemilihan model, status jangka panjang, dan penjadwalan. ThreadGrab menangani pengetahuan spesifik platform: cara membaca thread X, cara mengurai pos Bluesky, cara mengambil newsletter LinkedIn, cara menulis balik tanpa melanggar batas laju tiap platform. Batas MCP adalah kontrak antara keduanya, dan delapan alat yang diekspos ThreadGrab adalah kosakatanya.

Pembagian ini penting karena dua alasan. Pertama, Anda dapat menukar agen tanpa menulis ulang integrasi platform — MCP ThreadGrab yang sama bekerja di balik Claude Code, Windsurf, atau host bergaya Gemini di masa depan. Kedua, Anda dapat menukar platform tanpa menulis ulang agen — ketika ThreadGrab menambahkan dukungan Threads atau Mastodon, alat MCP yang sama mencakupnya, dan agen tetap bekerja tanpa perubahan.

Yang perlu diperhatikan dalam 30 hari ke depan

Tiga hal kemungkinan akan hadir sebelum Agustus. Yang pertama adalah marketplace Gemini Agents — Google telah memberi isyarat, dan tombol “pasang ThreadGrab” satu klik di dalam Gemini akan menghilangkan lima langkah di atas. Yang kedua adalah pelaporan biaya per token untuk panggilan MCP — saat ini penggunaan token loop agen digulung ke proyek, bukan ke alat. Yang ketiga adalah primitif “konfirmasi terjadwal”, di mana confirm_post dapat di-gate oleh aturan kalender alih-alih klik waktu nyata. Ketiganya akan memperluas jenis pekerjaan yang dapat Anda serahkan.

Penutup

Managed Agents Gemini dengan dukungan MCP jarak jauh adalah loop agen hosted pertama yang dapat menghubungi ThreadGrab tanpa kode perekat. Pengkabelan adalah lima langkah dan sepuluh menit. Batas yang penting — manusia-di-loop pada setiap pos keluar — ditegakkan oleh confirm_post, bukan oleh agen. Jika Anda memiliki pekerjaan pemantauan sosial yang perlu berjalan lebih lama dari satu sesi Claude Code, inilah cara paling bersih untuk menyerahkannya hari ini.

Frequently Asked Questions

Apa itu fitur Managed Agents Gemini, dalam bahasa sederhana?

Managed Agents adalah tugas latar belakang jangka panjang yang berjalan di dalam API Gemini Google. Anda mendefinisikan agen sekali — model, alat, system prompt — dan loop agen bertahan antar giliran. Anda dapat menjadwalkannya untuk bangun setiap beberapa jam, dan ia mempertahankan status percakapan di setiap kebangkitan. Ini adalah runtime agen hosted pertama dari lab besar dengan dukungan MCP jarak jauh kelas satu.

Apakah server MCP ThreadGrab memerlukan paket berbayar?

Alat hanya-baca (read_post, read_thread, search_timeline, archive_thread, archive_post) gratis untuk akun yang masuk. Alat tulis (draft_reply, draft_post) memerlukan paket Creator atau Pro. Kedelapan alat berbagi endpoint MCP yang sama dan model autentikasi bearer yang sama.

Bisakah Managed Agent Gemini memposting ke X tanpa manusia mengeklik konfirmasi?

Tidak. Alat confirm_post memerlukan token konfirmasi yang diterbitkan pengguna yang kedaluwarsa dalam lima menit. Agen dapat menyusun draf kapan saja, tetapi panggilan publikasi sebenarnya harus dipicu oleh tindakan manusia — baik klik di UI ThreadGrab, maupun token konfirmasi bertanda tangan yang dikembalikan oleh aplikasi Anda sendiri. Ini adalah aturan tegas di server, bukan kebijakan agen yang dapat dikonfigurasi.

Bagaimana ini berbeda dari dukungan MCP yang sudah ada di Claude Code?

Claude Code berjalan di terminal Anda sebagai sesi interaktif — berakhir saat Anda menutup jendela. Managed Agents Gemini berjalan di cloud Google dan bertahan antar sesi, sehingga dirancang untuk pekerjaan multi-hari yang bangun sesuai jadwal. Permukaan alat (delapan alat MCP ThreadGrab) identik; perbedaannya adalah apakah Anda ingin sesi yang diawasi atau pekerja latar belakang tanpa pengawasan.

Apa yang terjadi pada data yang dibaca agen melalui ThreadGrab?

Setiap panggilan baca dan tulis yang dilakukan agen dicatat ke arsip ThreadGrab pribadi Anda. Anda dapat menarik ekspor lengkap — setiap pos yang dilihat agen, setiap draf yang disusunnya, setiap token konfirmasi yang Anda terbitkan — kapan saja. Arsip diberi scope ujung-ke-ujung ke akun Anda dan tidak pernah dibagikan ke Gemini atau pihak ketiga mana pun.

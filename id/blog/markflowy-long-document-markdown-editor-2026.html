MarkFlowy v0.100: Editor Markdown Dibangun Ulang untuk Dokumen Panjang 2026

7 September 2026 · 9 menit baca · oleh ThreadGrab

Jika Anda punya satu file Markdown yang menyimpan setahun X Articles arsip, dump Substack, atau ekspor long-form Bluesky, kemungkinan Anda sudah menabrak tembok: VS Code butuh 6 detik untuk membukanya, Obsidian tersendat saat scroll, dan Typora diam-diam memutuskan untuk render ulang seluruh dokumen pada setiap ketukan tombol. Rilis MarkFlowy v0.100.0 pada 5 September 2026 adalah penulisan ulang inti editor secara menyeluruh yang ditujukan tepat pada beban kerja itu. Menurut catatan rilis, file Markdown 2 MB sekarang terbuka dalam sekitar 1 detik di laptop masa kini.

Kenapa threadgrab meliput ini: Arsip khas yang diekspor dari threadgrab (X Articles, threads, Bluesky long-form, newsletter LinkedIn) datang sebagai satu file .md yang dengan mudah melampaui 1 MB ketika Anda menggabungkan postingan satu bulan dari satu kreator. MarkFlowy v0.100 adalah editor desktop pertama yang sengaja dirancang untuk ukuran file itu tanpa kelambatan khas aplikasi Electron.

Apa yang Berubah di MarkFlowy v0.100.0

MarkFlowy adalah editor Markdown open-source berbantuan AI (AGPL-3.0, 2.382 bintang GitHub per 7 September 2026) yang dibangun di atas Tauri (TypeScript + Rust) dan ProseMirror. Rilis v0.100.0 pada 5 September 2026 secara eksplisit ditandai sebagai berisi perubahan besar yang substansial:

  • Inti editor dibangun ulang — parser, model dokumen, dan lapisan WYSIWYG ditulis ulang untuk memuat file besar lebih cepat.
  • 2 MB dalam ~1 detik — metrik utama dari catatan rilis; versi sebelumnya terasa jauh lebih lambat pada file di atas ~500 KB.
  • Rendering WYSIWYG disempurnakan — penjenjangan daftar, status task, dan format inline melakukan round-trip lebih rapi melalui sumber Markdown.
  • Kesadaran Front Matter — mengetik --- di awal dokumen sekarang membuat blok YAML front matter alih-alih garis horizontal (ditambahkan di v0.100.1 pada 6 September).
  • Indentasi daftar Tab / Shift+Tab — konten bertingkat, status task, dan riwayat undo/redo bertahan saat indentasi berubah.

v0.100.1 di hari berikutnya (6 September 2026) memperbaiki tiga regresi mode WYSIWYG yang diperkenalkan v0.100.0: toggle Full Width, hint Placeholder paragraf kosong, dan perilaku indentasi daftar. Jika Anda upgrade, simpan ulang dokumen yang sudah ada sekali agar representasi internal yang baru stabil.

Penulisan ulang MarkFlowy mendorong lebih banyak kerja ke parse awal yang lebih kecil, yang menjadi pembeda antara menunggu 6 detik dan menunggu 1.

Cara Pakai MarkFlowy dengan Arsip threadgrab

Alur gabungan punya bentuk yang sama dengan artikel scraper X Articles tapi MarkFlowy menggantikan langkah editor. Berjalan rapi dalam waktu kurang dari lima menit untuk arsip 1 MB:

Langkah 1 — Scrape sumber

curl -s "https://threadgrab.com/api/profile/<handle>/articles?cursor=&limit=100" \
  -o articles.json

+ Satu panggilan per penulis, dipaginasi 20 per kali, mengembalikan span badan entitas bernama

− Anda tetap perlu menggabungkan JSON jadi satu file Markdown

Langkah 2 — Gabung jadi satu .md

jq -r '.articles[] | "# " + .title + "\n\n" + .body_markdown + "\n\n---\n"' \
  articles.json > arsip-2026-09.md
wc -c arsip-2026-09.md   # konfirmasi ukuran

+ Markdown standar dengan front matter, separator, dan pemisah bagian yang rapi

− Memerlukan jq; di Windows pakai python -m json.tool atau skrip Node kecil

Langkah 3 — Buka di MarkFlowy v0.100

markflowy arsip-2026-09.md   # binari macOS / Linux
# atau klik dua kali file dari panel File Tree

+ Terbuka dalam ~1 detik; scroll tetap mulus; mode WYSIWYG memperbarui tanpa buka ulang

− Penggunaan pertama di macOS butuh xattr -cr /Applications/MarkFlowy.app sampai aplikasi ditandatangani

Langkah 4 — Penulisan ulang AI, bagian per bagian

# Di panel AI MarkFlowy, arahkan ke kunci DeepSeek atau ChatGPT Anda,
# lalu minta: "tulis ulang bagian 12 untuk menghilangkan hedging, pertahankan semua fakta."
# Tinjau diff di jendela yang sama, terima atau kembalikan per bagian.

+ Penulisan ulang per bagian mengalahkan tempel-kembali-dan-diff seluruh file dengan margin besar

− Anda harus membawa kunci API sendiri; MarkFlowy tidak menyertakan model bawaan

Langkah 5 — Publikasikan lewat md2rich atau situs statis

# Konversi Markdown yang sudah dipoles ke rich text untuk LinkedIn / Notion
curl -s "https://md2rich.com/api/convert?md_url=https://your-site/arsip-2026-09.md"

+ Markdown tetap jadi sumber kebenaran; rich text hanya sebuah render

− LinkedIn masih tidak konsisten menghormati tempel-dengan-format; sedikit perbaikan manual adalah wajar

Siapa yang Sebaiknya Beralih ke MarkFlowy v0.100

Penulisan ulang ini bukan untuk semua orang. Tiga profil pembaca paling diuntungkan:

  • Pemelihara arsip sosial. Jika Anda menyimpan satu .md per penulis atau per kuartal, MarkFlowy adalah editor pertama yang membuka file itu secara instan. File Tree menangani tata letak folder per penulis, dan panel AI dalam editor memungkinkan Anda menulis ulang satu bagian tanpa meninggalkan dokumen.
  • Penulis newsletter di platform long-form. Jika newsletter Substack atau LinkedIn Anda hidup sebagai satu Markdown sumber sebelum masuk platform publikasi, mode WYSIWYG MarkFlowy memberi pratinjau langsung yang tidak macet di 2 MB. Ekspor Pandoc yang ditambahkan di v0.90.0 (DOCX / ODT / EPUB) mencakup pengiriman sisi publikasi.
  • Penulis yang saat ini menyunting Markdown di VS Code dan merasakan kelambatan. Jika Anda sudah menonaktifkan Markdown All in One atau pindah ke Sublime karena VS Code lambat di arsip Anda, MarkFlowy memberi WYSIWYG tanpa beban VS Code. Sistem pintasan keyboard dapat disesuaikan, sehingga memori otot berpindah.

Tiga profil pembaca sebaiknya menunggu: siapa pun yang alurnya bergantung pada ekstensi VS Code tertentu, siapa pun yang timnya sudah membakukan diri pada ekosistem plugin Obsidian (Dataview, Templater, dll.), dan siapa pun yang menyunting file Markdown di bawah 200 KB (perbedaan kecepatan tidak terasa di ukuran itu).

Tumpukan di Balik Kecepatan

MarkFlowy adalah aplikasi Tauri: UI-nya TypeScript (3,86 MB sumber) dan sisi nativenya Rust (506 KB sumber). Editornya sendiri adalah build ProseMirror, dengan penulisan ulang v0.100 yang membangun ulang parser dan model dokumen untuk menunda rendering sampai bagian tertentu di-scroll ke tampilan. Biner tetap di bawah 20 MB dan mengirim ZIP portabel, MSI, dan installer offline untuk Windows; DMG untuk Apple silicon dan Intel di macOS; serta Flatpak (via FlatPark) plus skrip instalasi yang menaruh .deb / .rpm / AppImage di Linux.

Fitur AI adalah panel di dalam aplikasi, bukan layanan terpisah. MarkFlowy mendukung DeepSeek, ChatGPT, dan Copilot hari ini; Anda menyediakan kunci API sendiri, penulisan ulang terjadi di dalam editor, dan diff ditampilkan di jendela yang sama. Itulah beda praktisnya bagi seseorang yang menulis ulang arsip thread panjang: penyuntingan bagian per bagian tanpa meninggalkan dokumen, bukan tempel-kembali-dan-lihat-dengan-mata.

FAQ

Apa itu MarkFlowy dan mengapa v0.100 penting untuk file Markdown panjang?

MarkFlowy adalah editor Markdown open-source berbantuan AI yang dibangun di atas Tauri (TypeScript + Rust) dan ProseMirror, tersedia untuk Windows, macOS, dan Linux. Rilis v0.100.0 pada 5 September 2026 adalah penulisan ulang inti editor secara menyeluruh dengan perubahan besar; hasil utamanya adalah file Markdown 2 MB sekarang terbuka dalam sekitar 1 detik di laptop modern. Untuk arsip X Articles, dump wiki besar, dan postingan long-form dari media sosial yang digabung dalam satu file Markdown, ini perubahan berarti karena editor desktop lama (VS Code, Obsidian, Typora) melambat atau macet ketika file melewati ~500 KB struktur bertingkat.

Mengapa sudut dokumen panjang penting untuk arsip X dan Bluesky?

Arsip X Articles dari satu penulis saja sudah bisa melampaui 200 KB Markdown rapi ketika setiap postingan mempertahankan daftar media, format entitas bernama, dan frontmatter. Tumpuk setahun postingan long-form dari 10 kreator dan Anda mengedit di kisaran 2 MB yang sekarang diperlakukan MarkFlowy v0.100 sebagai beban normal. Hal yang sama berlaku untuk postingan long-form Bluesky yang diambil via AT Protocol, ekspor newsletter LinkedIn, dan dump RSS Substack. Editor yang men-tokenisasi ulang seluruh file saat dibuka menjadi bottleneck; pembangunan ulang MarkFlowy mendorong pekerjaan itu ke parse awal yang lebih kecil, yang persis seperti beban kerja yang dihasilkan arsip media sosial.

Bagaimana MarkFlowy dibanding VS Code, Obsidian, dan Typora pada file 2 MB?

Di perangkat keras yang sama, file Markdown 2 MB dengan ratusan bagian biasanya butuh VS Code 4 sampai 8 detik untuk dibuka dengan ekstensi seperti Markdown All in One aktif, Obsidian 3 sampai 6 detik dengan Live Preview, dan Typora sekitar 2 sampai 4 detik sebelum scroll mulus. MarkFlowy v0.100 melaporkan sekitar 1 detik pada file yang sama dalam pengujian mereka di laptop modern. Selisih utamanya paling besar di Windows, tempat editor berbasis Electron menambah overhead runtime di atas parse dokumen.

Bisakah saya pakai MarkFlowy untuk menyunting Markdown yang diekspor threadgrab?

Bisa. threadgrab mengembalikan Markdown rapi untuk postingan, thread, dan Articles X: setiap postingan mempertahankan span bold, link, mention, dan hashtag sebagai Markdown standar, dan ekspor batch bisa digabung jadi satu file. Buka file itu di MarkFlowy dan kecepatan buka 1 detik bertahan untuk arsip sampai sekitar 2 MB; lebih dari itu editor masih membuka tapi latensi mengetik mulai naik. Alur gabungannya: scrape dengan threadgrab → buka .md di MarkFlowy → edit, lint, dan tulis ulang → publikasikan ke Notion, Ghost, atau md2rich untuk konversi rich text.

Apa saja perubahan besar di MarkFlowy v0.100.0?

v0.100.0 membangun ulang inti editor, jadi beberapa perilaku penyuntingan dan interaksi berbeda dari versi sebelumnya. Catatan rilis menandai perubahan ini secara eksplisit dan menyarankan untuk menyimpan ulang dokumen yang berasal dari v0.90.x atau lebih lama. v0.100.1, yang dirilis sehari kemudian pada 6 September, memperbaiki toggle Full Width di mode WYSIWYG, mengembalikan hint Placeholder paragraf kosong, dan meningkatkan indentasi daftar dengan Tab / Shift+Tab. Dokumen baru tidak perlu tindakan apa pun; dokumen yang sudah ada sebaiknya disimpan ulang sekali setelah upgrade untuk menormalkan representasi internal baru.

Apakah MarkFlowy cocok untuk penulisan ulang AI pada Markdown panjang?

Cocok. MarkFlowy punya panel AI bawaan yang mendukung DeepSeek, ChatGPT, dan penyedia lainnya, dan dapat merangkum, menerjemahkan, atau menulis ulang dokumen Markdown panjang langsung di editor. Untuk alur threadgrab yang khas (scrape thread panjang, minta LLM membersihkannya, publikasikan ulang versi yang dipoles), MarkFlowy menjaga penulisan ulang tetap interaktif: Anda bisa meminta model mengubah satu bagian pada satu waktu, meninjau diff di jendela yang sama, dan hanya meng-commit bagian yang Anda suka. Itu lebih cepat daripada melewatkan seluruh file ke UI chat dan menempel hasilnya kembali.

Coba di Arsip Sungguhan

Cara tercepat merasakan akselerasi v0.100 adalah mengambil arsip kecil, menggabungkannya dengan jq, dan membuka .md hasilnya di MarkFlowy. File 2 MB (sekitar 600 postingan) adalah beban kerja di mana penulisan ulang terbayar, dan itu persis ukuran file yang dihasilkan arsip bulanan seorang kreator ketika Anda mempertahankan format entitas bernama.

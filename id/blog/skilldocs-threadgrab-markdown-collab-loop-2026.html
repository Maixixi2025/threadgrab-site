Skilldocs 2026: Lapisan Kolaborasi yang Hilang di Arsip Anda

29 Agustus 2026 · 7 menit baca · Alur Kerja

Tumpukan X-ke-Markdown di 2026 punya tiga lapisan, bukan dua. Lapisan tangkap (tweet.md, ThreadGrab, tweet-grab) mengubah sebuah thread menjadi Markdown polos. Lapisan agen (Claude Code, Cursor, Gemini CLI) membaca file dan melakukan pekerjaan. Bagian yang hilang — yang selalu diciptakan ulang tiap tim dengan komentar Notion, utas Google Docs, atau kebisingan tinjauan PR — adalah lapisan kolaborasi: tempat sebuah tim bisa mengedit SKILL.md bersama dengan komentar berlabuh, menyerahkannya ke agen, dan agen benar-benar memahami umpan baliknya.

Skilldocs, yang diluncurkan 12 Agustus 2026, adalah alat pertama yang saya lihat dibangun khusus untuk loop ini. Slogan mereka sendiri sudah tepat: lapisan kolaborasi untuk markdown tempat agen Anda berjalan. Sisa tulisan ini adalah arsitekturnya, alur kerja langsung yang saya uji, dan di mana Skilldocs cocok di samping ThreadGrab.

Ringkasan cepat: Skilldocs adalah lapisan tengah yang hilang di lini X → Markdown → agen. Ini editor CRDT dengan kursor langsung, komentar berlabuh yang bertahan dari pengeditan, dan server MCP yang menutup loop dengan Claude Code. Diluncurkan 12 Agustus 2026, dibangun oleh Rajiv Ayyangar, berjalan seluruhnya di skilldocs.dev/mcp lewat OAuth — tanpa bearer token, tanpa pemasangan lokal.

Apa sebenarnya Skilldocs itu

Skilldocs adalah satu permukaan editor, bukan layar terbagi. Judul, daftar, tabel, dan diagram Mermaid merender saat Anda mengetik; Markdown mentah muncul tepat waktu di sekitar kursor, sehingga Anda bisa melihat karakter literal yang disimpan buffer. File di磁盘 tetap Markdown polos, karakter demi karakter — yang Anda lihat di editor adalah yang akan Anda ketik dengan tangan.

Multipemain bersifat waktu nyata dan bebas konflik. Dokumen adalah CRDT, jadi pengeditan bersamaan menyatu karakter demi karakter. Tidak ada tombol simpan, dialog konflik, atau cara bagi dua orang untuk saling menimpa. Anda melihat kursor orang lain, seleksinya, dan namanya, dan bisa mengikuti pandangan siapa pun seperti berbagi layar. Komentar berlabuh ke kata-kata yang dibahasnya, bukan ke nomor baris, sehingga bertahan dari pengeditan di bawahnya.

Yang penting untuk situs ini adalah loop agen. Changelog dikirim dalam blok mingguan:

  • Minggu peluncuran (10–16 Agu): MCP-over-HTTP di skilldocs.dev/mcp, OAuth sesuai spec otorisasi MCP, plugin SKILL.md agar agen mendaftarkan loopnya bukan alatnya, pelabuhan komentar yang bertahan dari pengeditan, impor repositori dengan tempel.
  • 17–23 Agu: folder bersarang, skill listener (hook dua file yang menghitung skill yang benar-benar dijalankan tim), skilldocs_find untuk menyelesaikan dokumen mana yang file mana, dan push yang mengarsipkan dirinya sendiri ke folder.
  • Minggu ini (24–27 Agu): tabel yang merupakan editor langsung alih-alih gambar read-only, palet perintah ⌘K, mode fokus di ⌥⌘F, tema gelap, dan — perbaikan praktis — memisahkan "Skill calls" dari "MCP calls" di kolom penggunaan.

Entri changelog 24–27 Agustus tentang skill calls vs MCP calls adalah baris yang membuat saya menulis tulisan ini. Dokumen yang baru dibaca agen dulu terlihat seperti skill yang dijalankan seseorang, karena ringkasan menjumlahkan tiga peristiwa berbeda ke satu kolom. Sekarang ada dua kolom, keduanya bisa diurut, dan rel membuka halaman SKILLS yang mencantumkan setiap repositori terhubung dan setiap push lokal dengan asal di kolom kedua. Itulah jenis perbaikan yang hanya keluar saat tim sedang dogfooding loop pada skill mereka sendiri.

Loop, digambarkan

Begini alur kerja saat benar-benar berjalan, dengan Skilldocs di tengah. Setiap langkah punya alat dan keluaran.

1. TANGKAP   threadgrab (atau tweet.md)
   x.com / bsky.app / linkedin.com  -->  *.md  (satu file, teks polos)

2. TINJAU    Skilldocs (MCP, CRDT, OAuth)
   *.md  <--  tim mengedit + komentar berlabuh  -->  *.md  + utas

3. LAKUKAN  Claude Code / Cursor / Gemini CLI
   *.md + utas  -->  terapkan perubahan  -->  tulis kembali ke disk

4. KIRIM    git push / deploy
   *.md ditulis ulang  -->  repo  -->  hidup

Hal menarik tentang Skilldocs adalah langkah 2 dan langkah 3 berbagi format kawat. Agen mendorong skill lokal, tim mengedit dan mengomentari di Skilldocs, dan agen membaca kembali diff dan utasnya — lalu menjawabnya. Dari halaman tur, transkrip literalnya berbunyi:

Anda → dorong skills/release-notes/SKILL.md ke skilldocs
Ѕ1; skilldocs_open → skilldocs.dev/?doc=release-notes-writer
— tim mengedit dan mengomentari di SkillDocs —
Anda → baca diff dan komentar skilldocs, terapkan umpan balik, jawab utasnya
Ѕ1; skilldocs_diff → 2 bagian ditulis ulang sejak baseline
Ѕ1; skilldocs_comments → 2 utas terbuka dari Maya dan Sam
Ѕ1; skilldocs_reply → menjawab keduanya, menerapkan urutan ulang checklist
Ѕ1; skilldocs_pull → menulis dokumen kembali menimpa file lokal

Itulah loop dalam lima panggilan alat MCP. Tak satu pun bergantung pada agen tertentu — endpoint MCP bekerja di klien MCP mana pun, bukan hanya Claude Code. ChatGPT, Cursor, Gemini CLI, runner OpenAI Agents SDK kustom — semuanya berbicara MCP, jadi semuanya bisa mendorong skill, membaca diff, menjawab utas, dan menarik hasilnya kembali.

Apa yang ThreadGrab bawa ke langkah 1

Skilldocs mengasumsikan Markdown sudah ada. Itu tidak menangkap thread X, bentuk panjang Bluesky, postingan LinkedIn, atau apa pun dari web langsung. Itulah gunanya ThreadGrab, dan itulah lapisan yang tidak perlu dibangun Skilldocs karena alat seperti ThreadGrab sudah ada.

ThreadGrab menutup sisi tangkap dari loop:

  • Multi-platform — X / Twitter, Bluesky, LinkedIn, dan web headless lewat Workers + Browser Rendering. Skilldocs agnostic platform di sisi input karena inputnya adalah file.
  • Tangkap tanpa akun — API profil publik dan alur arsip per-handle tanpa autentikasi yang dibutuhkan untuk permukaan yang pengguna yang logout sudah bisa lihat.
  • Markdown teks polos — bentuk yang sama yang diharapkan Skilldocs: satu file dengan badan postingan, pohon utas, byline penulis, dan stempel waktu. Tanpa pembungkus JSON, tanpa skema proprietary.
  • UI tiga bahasa — EN / PT / ID, agar seorang pengarsip berbahasa Indonesia bisa mengirim tautan Skilldocs ke rekan setim tanpa terjemahan.

Penyerahannya mekanis: tangkap dengan ThreadGrab ke *.md lokal, dorong file itu ke Skilldocs (atau impor seluruh repositori dengan menempel URL-nya — Skilldocs memindai Markdown dan menunjukkan folder dengan semuanya tercentang), tinjau bersama tim, dan kirim file yang ditulis ulang kembali ke agen.

Apa yang Skilldocs bawa ke langkah 2

Tiga hal konkret, semuanya diverifikasi di situs langsung minggu ini:

1. MCP-over-HTTP, bukan pemasangan lokal

Server MCP dulunya adalah proses lokal. Sejak minggu peluncuran, endpoint tinggal di https://skilldocs.dev/mcp — tanpa Node, tanpa npx, tanpa clone. Berfungsi di klien MCP mana pun. Nama alat identik di kedua transport (HTTP dan stdio) supaya agen tidak perlu belajar nama kedua untuk hal yang sama di kawat berbeda.

2. OAuth, bukan bearer token

Bear token di header berarti kredensial workspace setahun melewati perintah shell dan masuk ke riwayat — dan berarti ChatGPT dan konektor claude.ai sama sekali tidak bisa autentikasi. Skilldocs sekarang menjadi authorization server-nya sendiri dan juga resource servernya, sesuai spec otorisasi MCP: discovery documents, dynamic client registration, layar persetujuan. Hubungkan dengan klik Allow.

3. Komentar berlabuh yang bertahan dari pengeditan

Sebuah utas dulunya hanya mengingat kata-kata yang dikutip ditambah indeks kemunculan, dan setiap klien mencari ulang dokumen untuk menempatkan sorotan — jadi mengedit di dalam kutipan membuat komentar yatim, dan dua orang yang mengedit bersamaan bisa sebentar tidak setuju utas merujuk ke kemunculan yang mana. Utas sekarang membawa pin posisi relatif yang menempel pada karakter itu sendiri: bertahan dari setiap pengeditan dan teridentifikasi sama di setiap klien, langsung dari CRDT.

Loop lengkap, ujung ke ujung

Ini runbook konkret yang saya uji minggu ini, dengan ThreadGrab di kiri, Skilldocs di tengah, Claude Code di kanan.

Langkah 1 — tangkap sebuah thread

Buka ThreadGrab, tempel URL thread, unduh Markdown. Untuk satu thread, itu satu file:

https://threadgrab.com/id/api/profile?handle=@example&thread=1745123456789012345
# Mengembalikan: thread-1745123456789012345.md (teks polos, ~6 KB)

Langkah 2 — dorong ke Skilldocs

Dari Claude Code, dorong file lokal sebagai skill:

// Di Claude Code dengan server MCP Skilldocs terhubung:
> push skills/release-notes/SKILL.md to skilldocs

// Skilldocs membuka dokumen baru di
//   https://skilldocs.dev/?doc=release-notes-writer

Langkah 3 — tinjau bersama tim

Buka URL di peramban. Kursor mendarat di dokumen, kursor nyata muncul untuk semua orang lain di workspace, dan rekan setim bisa meninggalkan komentar berlabuh dengan memilih frasa mana pun. Rel komentar mengurut berdasarkan urutan dokumen, bukan berdasarkan waktu utas dibuka.

Langkah 4 — baca diff dan utas kembali

> baca diff dan komentar skilldocs, terapkan umpan baliknya,
  jawab utasnya

// Mengembalikan:
// skilldocs_diff     -> 2 bagian ditulis ulang sejak baseline
// skilldocs_comments -> 2 utas terbuka dari Maya dan Sam
// skilldocs_reply    -> menjawab keduanya, menerapkan urutan ulang checklist
// skilldocs_pull     -> menulis dokumen kembali menimpa file lokal

Langkah 4 adalah hal yang baru. Sebelum Skilldocs, alur yang sama butuh tiga atau empat alat (Notion untuk komentar, GitHub untuk diff, utas Slack untuk percakapan, dan prompt "terapkan umpan balik" terpisah untuk agen). Sekarang satu endpoint MCP dan lima alat.

Di mana ini cocok di samping tweet.md

tweet.md, yang saya tulis 28 Agustus, adalah alat yang tepat untuk mengonversi satu postingan X, thread, Article, atau profil menjadi Markdown untuk vault Obsidian. Permukaan produknya lebih sempit daripada yang disarankan halaman muka: hanya X, keluaran teks polos, tanpa Bluesky atau LinkedIn. Retrospeksi lanskap memetakan di mana tweet.md cocok.

Skilldocs berada satu lapisan di atasnya: ini adalah tinjauan kolaboratif dari Markdown apa pun yang sudah Anda punya, entah itu datang dari tweet.md, ThreadGrab, Panache lint, atau SKILL.md yang ditulis tangan. Ketiganya bersama adalah tumpukan lengkap 2026 untuk pengarsip yang ingin arsip Markdown yang sudah ditinjau dan siap untuk agen:

LapisanAlatKeluaran
TangkapThreadGrab / tweet.md*.md polos
Edit / lintPanache, Marvellous, Writemark*.md bersih
KolaborasiSkilldocs*.md + utas berlabuh
ActingClaude Code / Cursor / Gemini CLI*.md ditulis ulang di disk
Kirimgit / wrangler / Cloudflare PagesHidup

Yang menarik di garis depan adalah lapisan kolaborasinya sekarang menjadi server MCP, yang artinya agen yang sama yang menulis SKILL.md di tempat pertama adalah agen yang membaca umpan balik tim dan menulis ulangnya. Loopnya menutup tanpa manusia menyalin komentar ke prompt.

Apa yang bukan Skilldocs

Beberapa batas yang jujur, karena saya sudah melihat setiap peluncuran "lapisan kolaborasi" tiga tahun terakhir:

  • Bukan alat tangkap. Jika sumbernya X atau Bluesky atau LinkedIn, ThreadGrab atau tweet.md harus jalan duluan. Skilldocs mengasumsikan file sudah ada.
  • Bukan alat publikasi. Ia menulis kembali ke file lokal lewat skilldocs_pull, bukan ke deploy situs statis. Itulah gunanya git push.
  • Bukan taman bermain free-tier. Tidak ada halaman harga yang dipublikasikan sampai hari ini. Workspace self-service gratis untuk disiapkan; biaya operasional ada di Skilldocs.
  • Bukan pengganti tinjauan kode. Untuk alur PR yang sesungguhnya, tinjauan GitHub + Claude Code masih jawabannya yang tepat. Skilldocs untuk SKILL.md dan dokumen yang menghadap agen, bukan untuk TypeScript.

Angka sorotan

Angka sorotan bagi saya adalah 24–27 Agustus. Dalam satu minggu Skilldocs mengirim: pengeditan tabel langsung (agar buffer tetap GFM polos saat pengeditan), palet perintah ⌘K, mode fokus ⌥⌘F, tema gelap dengan satu palet di seluruh rel / doc bar / editor, dan pemisahan skill-calls-vs-MCP-calls. Itu peluncuran ketiga dalam tiga minggu, di atas authorization server OAuth dan endpoint MCP-over-HTTP yang bekerja di klien mana pun. Irama peluncuran adalah bagian yang memberi tahu apakah sebuah alat hidup; daftar fitur memberi tahu apa yang dilakukannya.

FAQ

Apa itu Skilldocs?

Skilldocs adalah lapisan kolaborasi untuk Markdown tempat agen Anda berjalan. Diluncurkan 12 Agustus 2026. Ini adalah editor berbasis CRDT dengan kursor multipemain langsung, utas komentar berlabuh, dan server MCP agar agen mendorong skill, manusia mengedit dan mengomentari, dan agen membaca kembali diff dan utas.

Bagaimana Skilldocs cocok di antara threadgrab dan agen?

threadgrab menangkap thread X, profil, atau postingan LinkedIn sebagai Markdown. Skilldocs adalah tempat sebuah tim meninjau Markdown itu bersama, dengan komentar berlabuh dan kursor langsung. Server MCP lalu mengekspor dokumen beserta utasnya sebagai satu blob Markdown yang bisa dibaca dan dijalankan agen seperti Claude Code.

Apakah Skilldocs menggantikan threadgrab?

Tidak. threadgrab menangkap konten sosial asli (X, Bluesky, LinkedIn, web headless) dan menghasilkan Markdown. Skilldocs mengedit dan meninjau Markdown yang sudah ada. Keduanya berada di ujung berbeda dari loop yang sama: tangkap dengan threadgrab, tinjau dengan Skilldocs, kembalikan ke agen.

Apakah Skilldocs gratis?

Skilldocs belum punya halaman harga publik per 29 Agustus 2026. Produknya self-service (workspace, tanpa undangan) dan disertai endpoint MCP-over-HTTP di skilldocs.dev/mcp yang bisa dihubungkan klien MCP mana pun via OAuth. Tidak ada batas laju publik atau biaya per pengguna di dokumentasi yang terlihat.

Apa yang dilakukan server MCP Skilldocs?

Lima alat yang dicakup ke workspace Anda: skilldocs_open (buka dokumen), skilldocs_diff (bagian yang ditulis ulang sejak baseline), skilldocs_comments (utas terbuka), skilldocs_reply (jawab utas), skilldocs_pull (tulis dokumen kembali menimpa file lokal). Autentikasinya OAuth, bukan bearer token, sehingga kredensial workspace tidak pernah melewati perintah shell.

Siapa yang membangun Skilldocs?

Skilldocs dibangun oleh Rajiv Ayyangar. Situsnya diluncurkan 12 Agustus 2026 dengan editor CRDT, MCP-over-HTTP di skilldocs.dev/mcp, OAuth sesuai spec otorisasi MCP, dan plugin SKILL.md agar agen mendaftarkan loopnya, bukan hanya alatnya.

Cloudflare Computer 2026: Runtime Agen untuk Arsip Sosial

5 Agustus 2026 · 10 menit baca · oleh ThreadGrab

Pada minggu pertama Agustus 2026, Agents Week Cloudflare dibuka dengan judul yang sengaja provokatif: "Agen Anda membutuhkan komputer, bukan container." Posting itu memperkenalkan @cloudflare/computer, runtime agen pratinjau awal dan open-source yang memberi setiap agen filesystem tahan lama dan membiarkan platform memutuskan apakah sebuah tugas berjalan di isolate cepat, sandbox container Linux, atau browser web. Bagi siapa pun yang mengarsip konten panjang media sosial — X Articles, posting Bluesky, newsletter LinkedIn — pengumuman ini lebih penting dari yang terlihat: ambil, normalisasi, simpan, dan verifikasi adalah persis pipeline agen multi-langkah yang menjadi alasan runtime baru ini dibangun.

Panduan ini menjelaskan apa sebenarnya Cloudflare Computer itu (terverifikasi dari pengumuman resmi), bagaimana model workspace mengubah cara Anda menyimpan arsip Markdown, dan bagaimana menggabungkan runtime baru dengan normalisasi siap pakai ThreadGrab menjadi pipeline arsip sosial.

TL;DR. Cloudflare mengumumkan @cloudflare/computer (Agents Week, awal Agustus 2026) — runtime agen open-source di mana workspace (filesystem virtual berbasis SQLite di Durable Object) menyimpan file dan antarmuka exec() menjalankan tugas di isolate atau container. Untuk pengarsipan sosial, ini berarti korpus Markdown tahan lama dengan provenans, dengan ThreadGrab sebagai lapisan penangkapan dan normalisasi. Ini pratinjau awal: kunci versi dan periksa ulang ketersediaan sebelum digunakan di produksi.

Apa Itu Cloudflare Computer

Menurut pengumuman resmi di blog.cloudflare.com/cloudflare-computer, @cloudflare/computer adalah runtime agen di mana "detail dan mekanisme kode apa yang berjalan di isolate, sandbox container, atau browser web ditangani oleh platform." Runtime ini mengorkestrasi secara dinamis antara isolate yang cepat dan efisien dengan container Linux penuh "untuk memberi setiap agen komputer miliknya sendiri."

Proyek ini dirilis sebagai pustaka open-source, diinstal dengan npm install @cloudflare/computer. Motivasi yang dinyatakan Cloudflare adalah skala: memberi setiap agen container sendiri tidak akan berskala, karena di semua cloud tidak ada cukup komputasi bagi setiap perusahaan untuk memberikan lingkungan container ke agen setiap pengguna. Isolate adalah primitif yang efisien — taruhan yang sama yang dibuat Cloudflare dengan Workers sekitar sepuluh tahun lalu dan dengan Durable Objects sekitar enam tahun lalu. Tahun lalu, isolate mendapatkan kemampuan untuk membuat sandbox container sendiri, dan paket baru ini membungkus kedua primitif di balik satu abstraksi.

Catatan: ini pratinjau awal. Permukaan API dapat berubah sebelum rilis stabil, dan ketersediaan fitur harus diperiksa ulang sebelum Anda membangun alur produksi di atasnya.

Workspace: Filesystem Tahan Lama untuk Arsip Anda

Bagian inti dari @cloudflare/computer adalah workspace: filesystem virtual yang didukung SQLite dan dapat diisi dari penyimpanan cloud, kontrol versi, atau file apa pun yang Anda pilih. Ia menyediakan alat untuk membaca, menulis, dan mengedit file menggunakan Code Mode atau perintah bash, dan semua operasi dikontrol, diaudit, dan diamati — Anda mendapat kendali granular atas apa yang dapat disentuh agen.

Untuk pengarsipan sosial, ini terhubung langsung ke masalah "korpus arsip". Alih-alih menyebarkan file Markdown ke berbagai folder, workspace memberi rumah tahan lama dan berversi untuk setiap X Article, posting Bluesky, dan newsletter LinkedIn yang Anda tangkap, dengan jejak audit untuk setiap penulisan. Workspace dapat dibuat di Durable Object mana pun, sehingga filesystem berada di samping kode yang mengisinya.

Kelas Workspace juga mengekspos wrapper yang kompatibel dengan node:fs, yang berarti pustaka JavaScript yang ada yang mengharapkan filesystem dapat membaca dan menulis arsip tanpa adaptor khusus.

Runtime Eksekusi: Isolate atau Container, Dipilih per Tugas

Semua runtime eksekusi dalam paket ini berbagi antarmuka yang sama — exec(string, options) — dan dua disediakan langsung (Anda dapat menulis sendiri). Pengumuman itu mencatat bahwa agen ternyata sangat mampu memilih lingkungan yang tepat untuk tugas yang ada: pekerjaan yang hanya perlu memanipulasi file, memproses data, atau mengelola repositori git dapat berjalan di dalam isolate; perintah yang membutuhkan Linux, npm, atau biner native berjalan di dalam container.

Untuk pipeline arsip, pembagiannya alami. Isolate menangani langkah murah dan sering (ambil posting, ubah HTML ke Markdown, tulis file, hitung kata), dan container menangani langkah berat dan sesekali (jalankan markdownlint di korpus, ubah Markdown ke EPUB atau PDF, jalankan alat gambar native).

Workspace Arsip Sosial Minimal

Dua blok kode di bawah mengikuti API dari pengumuman resmi. Blok 1 menginstal paket dan membuat workspace di Durable Object, lalu menulis artikel yang ditangkap sebagai Markdown. Blok 2 menunjukkan antarmuka exec() dan backend container untuk pekerjaan yang lebih berat. Kode ini ilustratif dari API pratinjau — kunci versi dan periksa ulang dokumentasi sebelum digunakan di produksi.

# Install the open-source preview package
npm install @cloudflare/computer

# Create a durable archive workspace inside a Durable Object
import { Workspace } from "@cloudflare/computer";

const archive = new Workspace({ storage: this.ctx.storage });
await archive.fs.mkdir("/archive/2026", { recursive: true });
await archive.fs.writeText(
  "/archive/2026/x-article-2026-08-05.md",
  markdown
);

Setelah workspace ada, setiap posting yang ditangkap dapat ditulis ke jalur berisi tanggal. Karena filesystem didukung SQLite dan berada di Durable Object, arsip bertahan dari restart dan dapat dikueri seperti basis data jika Anda menyimpan indeks metadata.

# Run a command inside the workspace filesystem
const result = await archive.exec("bash", ["-c", "wc -l /archive/2026/*.md"]);
console.log(result.stdout);

import { withWorkspaceContainer } from "@cloudflare/computer/backends/container";

  override workspaceBash = false;

Membangun Pipeline Arsip Agen untuk X, Bluesky, dan LinkedIn

Pipeline praktis untuk 2026 memiliki lima langkah. Pertama, ambil posting publik — X Article, posting panjang Bluesky, atau newsletter LinkedIn. Kedua, normalisasi ke Markdown dengan alat seperti ThreadGrab: tempel URL dan terima Markdown atau JSON bersih dengan URL asli dan stempel waktu yang dipertahankan. Ketiga, tulis Markdown ke workspace di jalur berisi tanggal. Keempat, jalankan verifikasi di dalam isolate — periksa tautan yang terselesaikan, hitung kata, konfirmasi URL kanonis ada. Kelima, untuk pekerjaan yang lebih berat seperti membuat EPUB dari arsip minggu ini, pindah ke runtime container, lalu commit workspace ke git sebagai snapshot tahan lama.

Pembagian kerja itu penting. ThreadGrab adalah lapisan normalisasi yang dapat Anda gunakan hari ini, tanpa langkah build; Cloudflare Computer adalah runtime yang akan Anda gunakan jika ingin mengotomatiskan seluruh loop sebagai agen. Sebagian besar kreator sebaiknya mulai dengan ThreadGrab dan menambahkan runtime agen hanya ketika volume posting yang diarsipkan membenarkannya.

Provenans adalah bagian yang mudah dilewati dan sulit dipulihkan. Simpan URL asli posting, platform, stempel waktu penangkapan, dan (jika tersedia) ID posting di platform itu sendiri di samping Markdown. Workspace mengubahnya menjadi konvensi, bukan disiplin: jalur penulisan yang sama selalu dapat menyertakan header metadata kecil.

Isolate vs Container untuk Pengarsipan

Lingkungan Terbaik untuk Profil biaya Kasus penggunaan arsip
Isolate (Workers) Manipulasi file, pemrosesan data, operasi git Cepat, overhead rendah, cold start dalam milidetik Ambil posting, ubah HTML ke Markdown, tulis file, hitung kata
Sandbox container Alat Linux, paket npm, biner native Lebih berat, sesuai permintaan, beberapa detik untuk mulai markdownlint, pandoc, konversi EPUB/PDF, pemrosesan gambar
Runtime browser Render UI dan verifikasi tangkapan layar Muncul dalam pratinjau Pemeriksaan visual artikel yang dirender sebelum diarsip (periksa ketersediaan saat ini)

Catatan: Perangkat Lunak Pratinjau dan Disiplin Verifikasi

Tiga peringatan sebelum Anda membangun. Pertama, @cloudflare/computer adalah pratinjau awal — pengumuman itu eksplisit bahwa proyek ini adalah eksperimen yang dirilis "untuk belajar bersama pelanggan kami." Perlakukan API sebagai sesuatu yang bergerak. Kedua, klaim bahwa agen memilih lingkungan yang tepat secara andal berasal dari pengumuman Cloudflare; ujilah pada beban kerja arsip Anda sendiri sebelum mempercayainya. Ketiga, beberapa kemampuan yang disebutkan dalam pengumuman (seperti lingkungan eksekusi browser web) mungkin tidak tersedia langsung — paket ini menyediakan dua runtime hari ini, dan ketersediaan harus diperiksa ulang.

Keterbatasan

Pratinjau ini bukan produk terhosting: Anda menjalankannya di Cloudflare Workers dengan Durable Objects, yang berarti Anda perlu akun Cloudflare, proyek Workers, dan nyaman dengan JavaScript sisi server. Ia juga tidak menyelesaikan masalah konten: artikel LinkedIn berbayar atau posting X yang terhapus tetap perlu ditangkap sebelum hilang — runtime agen hanya membuat loop penangkapan lebih mudah diotomatisasi. Terakhir, kualitas pengarsipan tetap bergantung pada lapisan normalisasi Anda; runtime tidak menilai apakah Markdown yang Anda simpan setia pada aslinya.

FAQ

Apa itu Cloudflare Computer?

Cloudflare Computer adalah runtime agen pratinjau awal di balik paket npm @cloudflare/computer, diumumkan oleh Cloudflare selama Agents Week 2026. Runtime ini memberi setiap agen filesystem virtual tahan lama (workspace) dan membiarkan platform memutuskan apakah sebuah tugas berjalan di isolate cepat, sandbox container Linux, atau browser web. Pengumuman itu memposisikannya sebagai komputer, bukan container, untuk agen.

Apa bedanya workspace dengan folder biasa?

Workspace adalah filesystem virtual yang didukung SQLite dan dapat diisi dari repositori git, bucket penyimpanan, atau file apa pun yang Anda pilih. Ia menyediakan alat baca, tulis, dan edit yang diaudit, dapat dibuat di Durable Object mana pun, dan mengekspos wrapper yang kompatibel dengan node:fs, sehingga berperilaku seperti filesystem yang bertahan dari restart dan menyimpan jejak audit.

Apakah Cloudflare Computer sudah bisa digunakan hari ini?

Ya, sebagai pratinjau open-source. Anda menginstalnya dengan npm install @cloudflare/computer dan menjalankannya di Workers dengan Durable Objects. Karena ini pratinjau awal, perlakukan API sebagai sesuatu yang bergerak: kunci versi, baca dokumentasi terkini, dan periksa ulang ketersediaan sebelum membangun pipeline arsip produksi di atasnya.

Mengapa runtime agen penting untuk pengarsipan sosial?

Karena mengarsip X Articles, posting Bluesky, dan newsletter LinkedIn adalah loop berulang multi-langkah: ambil, normalisasi ke Markdown, simpan dengan provenans, dan verifikasi. Runtime dengan filesystem tahan lama dan lingkungan eksekusi per tugas mengubah loop itu menjadi sesuatu yang dapat dijalankan agen tanpa pengawasan, dengan isolate untuk langkah murah dan container untuk pemrosesan berat.

Apakah Cloudflare Computer menggantikan ThreadGrab?

Tidak, keduanya saling melengkapi. ThreadGrab adalah alat siap pakai yang menormalisasi posting publik dari X, Bluesky, Threads, Substack, dan LinkedIn menjadi Markdown atau JSON bersih hari ini, tanpa langkah build. Cloudflare Computer adalah runtime bagi pengembang yang ingin mengotomatiskan seluruh loop arsip sebagai agen. Pengaturan pragmatis 2026 adalah ThreadGrab untuk penangkapan dan normalisasi, plus runtime agen hanya ketika volume membenarkannya.

Apa saja keterbatasan pratinjau ini?

Ini bukan layanan terhosting: Anda perlu proyek Workers dengan Durable Objects. Paket ini menyediakan dua runtime eksekusi bawaan (isolate dan container), dan Anda menulis sendiri untuk kebutuhan lain. Ia juga tidak dapat memulihkan konten yang tidak pernah ditangkap: posting berbayar atau terhapus tetap harus disimpan sebelum hilang.

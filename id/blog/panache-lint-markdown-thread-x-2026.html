Mengapa Thread yang Diambil Perlu Formatter dan Linter

Tangkapan thread adalah salinan setia dari sumbernya, yang memang Anda inginkan untuk arsip — tetapi jarang seperti yang Anda ingin terbitkan. Saat Anda mengonversi thread multi-postingan menjadi Markdown, hasilnya cenderung memiliki:

  • Lebar baris yang tidak konsisten. Setiap penulis membungkus teks dengan cara berbeda, sehingga file yang diambil mencampur baris pendek dan panjang.
  • Gaya daftar yang campur aduk. Sebuah thread mungkin memakai 1., -, dan * secara bergantian, dan menempelkannya ke editor menghasilkan render yang tidak konsisten.
  • Pembungkusan tidak rata. Aliran paragraf berbeda dari satu postingan ke postingan lain, sehingga file terbaca tidak merata.
  • Blok kode yang tidak diformat. Tweet yang berisi kode atau konfigurasi tiba sebagai teks mentah tanpa indentasi atau gaya sintaks yang konsisten.

Semua ini tidak merusak render, tetapi semuanya membuat Markdown lebih sulit diedit dan kurang profesional saat Anda menerbitkan ulang. Formatter menormalkan struktur; linter memberi tahu apa yang perlu diperbaiki; perbaikan otomatis melakukannya untuk Anda.

Apa yang Dilakukan Panache (Terverifikasi)

Panache adalah open source di GitHub (lisensi MIT), ditulis dalam Rust, dan didistribusikan melalui lusinan kanal termasuk cargo install, Homebrew, npm, PyPI melalui uv tool atau pipx, serta skrip instalasi resmi. Tiga kemampuan penting untuk alur penerbitan ulang:

  • Pemformatan — memformat ulang file di tempat, dari stdin, atau lintas pola glob, dengan lebar baris dan gaya reflow yang dapat dikonfigurasi. Pemformatan bersifat idempoten, sehingga menjalankannya dua kali memberi hasil yang sama.
  • Linting — melaporkan masalah format dengan panache lint, dan opsional memperbaiki otomatis. Flag --check pada format memverifikasi apakah file sudah bersih tanpa mengubahnya, sempurna untuk CI.
  • Formatter dan linter eksternal untuk blok kode — menjalankan Prettier pada JavaScript, ruff atau black pada Python, atau alat Anda sendiri pada fenced code blocks di dalam Markdown, menjaga setiap contoh kode tetap konsisten.

Ia juga menyertakan language server (LSP) lengkap untuk fitur editor — diagnostik, code action, outline dokumen, dan lompat ke definisi referensi — sehingga mesin yang sama bekerja di dalam VS Code atau editor pilihan Anda. Halaman performa membandingkannya dengan Prettier, mdformat, markdownlint, dan lainnya, dan halaman perbandingan menunjukkan persis di mana ia menangani sintaks Quarto/Pandoc yang tidak dicakup alat yang lebih lama.

Instal Panache

Pilih metode instalasi yang sesuai dengan mesin Anda. Di macOS dan Linux, skrip resmi adalah jalur terpendek:

# Skrip instalasi resmi (macOS / Linux)
curl --proto '=https' --tlsv1.2 -sSf https://panache.bz/install | sh

# Atau melalui manajer paket
cargo install --locked panache
brew install panache
npm install -g @panache-cli/panache
uv tool install panache-cli   # atau: pipx install panache-cli

Setelah terinstal, pastikan alat berfungsi:

panache --version
panache format --help

Langkah 1 — Ambil Thread, Lalu Format

Konversikan thread publik X ke Markdown dengan ThreadGrab, lalu normalisasi dengan panache format. Tahap pengambilan memberi Anda sumber yang setia; tahap pemformatan memberi Anda sumber yang bersih.

# 1. Ambil thread publik X sebagai Markdown bersih
threadgrab https://x.com/you/status/1234567890123456789 \
  --output ./drafts/thread-2026-08.md

# 2. Format di tempat, rapikan ke lebar baris yang Anda pilih
panache format ./drafts/thread-2026-08.md

# 3. Atau kirim satu file melalui stdin
cat ./drafts/thread-2026-08.md | panache format

Panache membaca konfigurasinya dari .panache.toml di direktori saat ini atau direktori induk, sehingga Anda dapat menetapkan gaya sekali dan menggunakannya kembali di setiap file yang diambil. Konfigurasi minimal yang merapikan paragraf ke lebar baris yang nyaman terlihat seperti ini:

# .panache.toml
[format]
wrap = "reflow"
line-width = 80
line-ending = "auto"

Langkah 2 — Lint dan Perbaiki Otomatis Sebelum Terbitkan Ulang

Sebelum menerbitkan ulang, jalankan linter untuk menangkap apa pun yang tertinggal dari pemformatan, dan biarkan ia memperbaiki yang bisa:

# Laporkan masalah format di semua thread yang diambil
panache lint ./drafts/*.md

# Verifikasi apakah file sudah bersih (kode keluar non-nol jika belum)
panache format --check ./drafts/thread-2026-08.md

# Format + perbaiki seluruh direktori tangkapan sekaligus
panache format ./drafts/**/*.md

Karena --check mengembalikan kode keluar yang bermakna, Anda dapat memasukkannya ke skrip atau job CI mana pun: jika thread yang diambil belum diformat, job gagal dan Anda tahu persis file mana yang perlu diperbaiki.

Langkah 3 — Jaga Blok Kode Konsisten dengan Formatter Eksternal

Thread yang berisi kode atau konfigurasi adalah tempat pemformatan benar-benar terbayar. Panache menjalankan formatter eksternal pada fenced code blocks, sehingga Anda menjaga setiap contoh kode konsisten dengan alat yang sudah Anda gunakan. Tambahkan bagian [formatters] ke konfigurasi Anda:

[formatters]
python = ["isort", "black"]
javascript = "prettier"
typescript = "prettier"

[formatters.prettier]
prepend-args = ["--print-width=100"]

Sekarang, saat Anda memformat thread yang diambil berisi cuplikan Python atau JavaScript, Panache meneruskan blok-blok itu melalui isort + black atau Prettier secara otomatis. Markdown naratif dinormalisasi oleh Panache; kode yang disematkan dinormalisasi oleh alat yang sudah distandarkan proyek Anda.

Langkah 4 — Terapkan Otomatis dengan Pre-commit atau CI

Langkah terakhir adalah menghilangkan kebutuhan untuk mengingat. Panache menyediakan hook pre-commit dan GitHub Action khusus, sehingga setiap file Markdown yang diambil diformat dan dilint sebelum masuk ke repositori atau keluaran yang diterbitkan.

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/jolars/panache-pre-commit
    rev: v3.4.0
    hooks:
      - id: panache-format
      - id: panache-lint
# GitHub Actions — di file workflow Anda
- uses: jolars/panache-action@v1

Dengan hook pre-commit terpasang, pipeline menjadi sepenuhnya otomatis: ambil thread dengan ThreadGrab, buat commit, dan Panache memformat + melint sebelum commit tersimpan. Markdown bersih menjadi standar, bukan pengecualian.

Panache vs. Alat Lain

Halaman perbandingan di README memposisikan Panache terhadap Prettier, mdformat, markdownlint, marksman, dan alat serupa. Versi singkat untuk penerbitan ulang thread:

AlatTerbaik untukDi mana Panache berbeda
PanacheQuarto/Pandoc/R Markdown, LSP, formatter blok kodeSatu CLI untuk format + lint + perbaikan otomatis + editor
PrettierMarkdown gaya JavaScript, format kodeGagal pada beberapa fenced div Quarto dan sintaks tabel
mdformatPemformatan Markdown sederhanaTidak ada LSP, tidak punya kesadaran Quarto/R
markdownlintAturan lintingHanya linter; tanpa formatter, tanpa alat blok kode

Untuk Markdown sederhana, Anda dapat menggunakan Panache sebagai formatter dan linter pengganti langsung; untuk dokumen Quarto atau R Markdown — atau ketika Anda menginginkan pengalaman editor berbasis LSP — ia menangani kasus yang tidak bisa ditangani alat yang lebih lama.

FAQ

Apa itu Panache dan apa fungsinya dengan Markdown?

Panache adalah language server, formatter, dan linter untuk Markdown, Quarto, dan R Markdown, ditulis dalam Rust dengan parser concrete syntax tree (CST) tanpa kehilangan data. Ia menyediakan satu CLI yang dapat memformat file di tempat, melint-nya untuk masalah format, memperbaiki secara otomatis, dan menjalankan server LSP untuk integrasi editor. Ia juga mendukung menjalankan formatter dan linter eksternal (seperti Prettier, ruff, atau black) pada blok kode di dalam dokumen Markdown Anda.

Mengapa saya perlu memformat dan melint Markdown yang diambil dari thread X?

Thread yang diambil adalah salinan setia, bukan versi yang dirapikan: postingan tiba dengan lebar baris yang tidak konsisten, gaya daftar yang campur aduk, paragraf dengan pembungkusan tidak rata, dan blok kode yang tidak pernah diformat. Sumber yang berantakan itu sulit diedit dan diterbitkan ulang. Menjalankan formatter menormalkan pembungkusan, merapikan paragraf ke lebar baris yang Anda pilih, dan memperbaiki otomatis masalah daftar serta spasi, sehingga Markdown menjadi file sumber yang bersih dan profesional.

Apakah Panache merupakan alternatif dari Prettier atau mdformat?

Panache tumpang tindih dengan alat-alat tersebut tetapi dibangun di sekitar sintaks Quarto, Pandoc, dan R Markdown, yang tidak sepenuhnya ditangani Prettier dan mdformat (misalnya fenced div dan sebagian sintaks tabel). Ia juga menambahkan language server LSP, linter terintegrasi dengan perbaikan otomatis, pemformatan glob rekursif, dan formatter blok kode eksternal. Untuk Markdown sederhana, Anda sering dapat menggunakannya sebagai pengganti langsung; untuk dokumen Quarto atau R Markdown, ia menangani sintaks yang tidak didukung alat yang lebih lama.

Bisakah saya menjalankan Panache pada thread yang diambil secara otomatis sebelum menerbitkan ulang?

Ya. Panache memiliki hook pre-commit khusus dan GitHub Action, sehingga Anda dapat memformat dan melint setiap file Markdown yang diambil secara otomatis di CI atau sebelum setiap commit. Anda juga dapat memanggilnya dalam loop shell satu baris pada direktori thread yang diambil, atau mengirim satu file melalui stdin dengan panache format. Ini memudahkan menjaga setiap thread yang diambil tetap bersih tanpa harus menjalankannya secara manual.
